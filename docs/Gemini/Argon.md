# 基于DeepSeek Harness与前沿智能体架构的全自治个人Agent系统深度研究报告

## 范式转移：从单一模型调用到时空可组合的智能体运行时底座

2026年下半年，人工智能领域的工程与学术演进确立了一条核心公理，即智能体等于基座模型与运行时底座的结合（$\text{Agent} = \text{Model} + \text{Harness}$）。在这一范式下，基座大语言模型（如 DeepSeek-V4-Pro、DeepSeek-V4-Flash、Claude Opus 或 GPT-5.6 Sol）仅作为提供概率推理与符号生成的权重层，而决定智能体能否在真实物理与数字世界中长期存活、自主探索、安全交互并自我演化的关键，则全面上移至被称为 Harness（运行时底座或控制鞍具）的基础设施层。传统的智能体产品（如 Claude Code、Codex 或 OpenClaw）大多采用将发动机焊死在车架上的封闭式垂直集成架构，开发者与高级用户无法在不分叉底层源码的前提下替换其记忆管理、事件循环（Agent Loop）或权限门控机制。

2026年8月13日，DeepSeek 官方与 DeepSeek-V4-Pro 及 V4-Flash 同步开源了采用 MIT 协议的 DeepSeek Harness（命令行标识为 `dsh`），该框架在发布一周内即斩获 16.5 万 GitHub Stars，截至 2026 年 10 月总星标数已突破 246.8k Stars，社区涌现出超过 2,600 个遵循 `dsh.bundle` 规范的插件仓库，收录于 `awesome-dsh-plugin`（18.6k Stars）等精选目录中。DeepSeek Harness 之所以引发智能体工程界的剧烈震荡，源于其底层基于元框架 Cordis 构建的“一切皆插件（Everything is a Plugin）”设计哲学与“时空可组合性（Spatiotemporal Composability）”理论。在空间可组合性（Spatial Composability）维度，模型适配器、工具集、会话存储、沙箱环境、调度器、UI 界面乃至核心的 Agent Loop 本身均作为平等的 Cordis 插件挂载，各插件通过共享服务目录（如 `ctx.tools`、`ctx.llm`、`ctx.sessions`、`ctx.agents`）声明依赖关系，无需硬编码启动序列即可在依赖满足时自动激活，实现了机架式服务器插槽般的热插拔解耦。在时间可组合性（Temporal Composability）维度，Cordis 4 的轻量级协程单元（Fiber）精确追踪每个插件在生命周期内注册的事件监听器（如 `agent/step`、`agent/settled`）、系统提示词片段与工具 Schema；当插件被卸载或热替换时，其挂载的所有运行时副作用（Effects）会被可逆地自动回滚清理，杜绝了长周期运行中的孤儿监听器与内存泄漏，配合仅追加（Append-only）的事件日志流，任何会话均支持帧级回放（Replay）、分叉（Fork）与断点恢复（Resume）。此外，全天候运行的个人自治智能体单次复杂任务往往消耗 500K 以上的 Tokens，DeepSeek Harness 搭配稀疏 MoE 架构的 DeepSeek-V4-Flash（总参数量 284B，每次前向传播仅激活 13B 参数），将输入与输出成本压低至 $0.14 与 $0.28 每百万 Tokens，且上下文缓存命中（Cache Hits）成本仅 $0.0028 每百万 Tokens，在保持 53.3% 相同任务通过率的前提下，单次成功任务的运行成本从封闭式商业底座的 $0.195 骤降至 $0.045，单位经济效益提升达 30 至 100 倍。

## 感知、调度与闭环推荐层：跨平台信息采集与主动情报哨兵

前三个功能需求共同构成了个人智能体的主动信息摄取与反馈适应闭环（Perception-Scheduling-Preference Loop）。尽管三者均包含“信息搜集、主动报告以及根据用户反馈调整下一次推荐偏好”的共性逻辑骨架，但在底层触发机制、信息模态特征与外部信源拓扑上呈现出截然不同的系统工程要求：功能一聚焦于跨平台多模态视觉审美对齐（Cron 定时批处理），功能二聚焦于高认知密度学术文献的快慢思考筛选（Cron 定时批处理），而功能三则属于低信噪比公网环境下的事件驱动型实时哨兵（Event-Driven Streaming Sentinel）。

### 功能一：二次元角色美图每日定时搜集与反馈驱动审美对齐

在执行“每天收集白厄（Phainon）的美图，晚上9点准时报告，并根据用户反馈调整下一天推荐偏好”这一任务时，传统基于关键词匹配的爬虫与简单提示词重排面临双重失效困境。一方面，二次元插画的美学质量（如构图张力、光影层次、画风还原度及同人二创意境）属于高维潜在视觉特征，表层标签匹配极易混入低质生成图像或崩坏画面；另一方面，用户每日晚间给出的反馈往往是高度简略或异构的（例如对某张图像点击收藏，而对另一张评论偏好战损高光氛围），如何在不微调大模型参数的前提下，将先验任务约束与每日增量的后验交互信号融合为精准的次日检索策略，是该模块的核心学术难题。

2026年9月12日发表的论文 *P3Rec: Distilling Prior--Posterior Preference Reasoning for LLM-based Recommendation*（`arXiv:2609.13993`，作者 Jinfei Chen、Weihai Lu、Jiawei Cheng）为此提供了严密的理论解法。现有将大语言模型作为推荐增强器（LLM-as-Enhancer）的方法通常仅依赖静态历史先验进行单向推理，忽略了真实推荐结果展示后用户即时反馈所蕴含的后验修正信号。`P3Rec` 提出了先验—后验偏好推理蒸馏框架（Prior–Posterior Preference Reasoning Distillation），首先基于用户显式任务指令与既有历史档案构建先验偏好推理分布 $P_{\text{prior}}(y \mid u, c)$，随后在每日 21:00 推送并获得用户真实交互反馈 $f_t$ 后，显式计算后验偏好状态 $P_{\text{post}}(y \mid u, c, f_t)$ 与先验预期之间的认知残差（Discrepancy），并将这种高阶对比推理蒸馏到轻量级检索与重排表征中，从而在保证高效检索的同时实现完备的动态偏好演进。与此同时，入选 ACM RecSys '26（2026年9月26日提交 arXiv）的论文 *Mend the Measurement Gap: Latent User Preference Modeling for Short-Form Video Recommendation*（`arXiv:2609.32839`）进一步解决了视觉媒体推荐中的“测量鸿沟”问题。该研究指出，用户在浏览视觉内容时的显式与隐式行为反馈存在天然噪声与不完整性；通过构建潜在用户偏好模型（Latent User Preference Model）过滤表层交互噪声并对齐深层审美愉悦度，该机制在 YouTube Shorts 线上 A/B 测试中将核心观看愉悦度指标显著提升了 2.67%。

在 DeepSeek Harness 生态中，实现该功能最成熟且星标最高的插件组合是 `whiteguo233/dsh-openbiliclaw`（主项目 `OpenBiliClaw` 拥有 3.4k Stars，最新迭代版本达 `v0.3.227`）配合全网星标第一的视觉桥接插件 `liustack/modlens`（4.2k Stars）以及官方 `Scheduled tasks`（或 `dsh-loop`）定时引擎。`OpenBiliClaw` 原生覆盖 B站、小红书（RedNote）、抖音、YouTube、X（Twitter）、知乎、Reddit、Bangumi、微博、实验性 Instagram 与开放 Web 等全部二次元核心图源。其 DSH 客户端插件通过本地 `/api/image-proxy` 接口自动归一化小红书与 X 等平台的防盗链 CDN URL，并以 16:9 高清大图卡片（附带匹配度百分比胶囊与推荐理由）渲染在 DSH 界面右侧滑出抽屉（`shell.overlay`）中。配合 `OpenBiliClaw` 内置的“P1 视觉画像 / P3 关键帧多模态处理”以及 `liustack/modlens`（或 `@anionex/dsh-vision-toolkit`），纯文本的 DeepSeek-V4 模型获得了结构化的 JSON 视觉证据提取能力（涵盖版面构图、实体关系与画质评估），从而在入库前剔除低质图源。通过启用 DSH 官方 `Scheduled tasks` 插件设定每日北京时间 21:00 触发，智能体自动调用 `dsh-openbiliclaw` 注册的 22 个 `openbiliclaw_*` 工具（基于 Agent Bridge v2 CLI）拉取当日精选的“白厄”高分美图合集呈报用户。用户在面板卡片内点选“喜欢、收藏、少来点、聊一聊”或直接输入自然语言反馈后，智能体立即调用 Bridge 工具将反馈写回本地 SQLite 数据库中的五层画像（Event → Preference → Awareness → Insight → Soul），自动修正次日的搜索词生成模式与视觉评估权重。

### 功能二：AI自进化最新论文成果每日追踪、精读与偏好演化

每日收集“AI自进化（Self-Evolving AI / Agent Self-Improvement）”领域的最新论文成果并在晚上 9 点准时报告，其核心工程挑战在于处理海量预印本流的高认知负载与多轮反馈中的偏好漂移。arXiv 每日新增数以千计的计算机科学文献，若仅靠表层向量相似度检索，极易将常规微调或传统进化计算论文误报；若对每篇候选文献均调用深度推理模型进行全文解析，Token 成本与响应延迟又将失控。此外，随着用户在连续多日的反馈中不断强调特定学术偏好（例如偏好保持权重不变的运行时自进化，排斥纯强化学习权重更新），基于 LLM 的推荐系统极易产生“身份提示偏好漂移（Identity-Cue Preference Drift）”，即过度迎合历史标签而漏掉跨学科的突破性研究。

2026年9月2日发表的论文 *Recommender System as Slow and Fast Thinkers*（`arXiv:2609.02671`，Zichen Yuan 等 11 位学者合著）首次将双系统认知理论形式化为自适应推理推荐架构。该框架设计了快思考通道（System 1 - Fast Thinker）与慢思考通道（System 2 - Slow Thinker）：快思考通道以极低算力开销扫描全量候选文献池（如当日 `cs.AI`、`cs.CL`、`cs.LG`、`cs.MA` 列表），基于高召回率的表层语义特征快速过滤出与“AI自进化”相关的候选子集；慢思考通道则针对进入精筛池的论文以及用户前一日给出的复杂方法论反馈，动态分配高推理努力（Reasoning Effort），展开多步因果推理链比对论文的核心方法论贡献与用户深层学术品味，实现计算效率与推荐深度的自适应平衡。同时，2026年9月28日发表的 *Measuring and Mitigating Identity-Cue Preference Drift in LLM-based Recommender Systems*（`arXiv:2609.34229`，Zhuoxiong Gan、Qiang Dong）证明了在多轮反馈循环中，LLM 推荐器会因上下文中的用户身份与历史偏好线索产生系统性偏差放大，并提出了一种无需任何模型训练（Training-free）的偏好漂移度量与消偏校准机制，辅以 *FacetCRS*（`arXiv:2609.20175`）的多面相偏好学习破茧机制，确保每日学术报告既能紧密跟随用户反馈演化，又不会陷入狭窄的信息茧房。

在 DeepSeek Harness 生态中，针对每日 21:00 的 AI 自进化论文追踪与报告，最成熟的插件方案是工具榜排名榜首的 `alaliqing/claude-paper`（268 Stars，支持通过 `dsh plugin add github:alaliqing/claude-paper` 直接挂载）配合专为智能体打造的学术搜索插件 `taxueseek/argo`（55 Stars）。`taxueseek/argo` 内置独立的“学术”与“代码”多语言搜索通道，每日晚间定时任务启动后，智能体首先调用 `argo` 执行快思考初筛，检索过去 24 小时内 arXiv、GitHub 与 HuggingFace Papers 上关于自进化智能体的最新条目。随后，智能体调用 `alaliqing/claude-paper` 执行慢思考精读，自动拉取入选论文的源码与全文，生成结构化的研究精读摘要、提炼核心数学公式与实验对比表格、自动构建可运行的最小代码验证演示（Code Demonstrations），并渲染出交互式 Web 阅读视图于 21:00 准时呈交。结合 `csyangwen/dsh-memory-evolve` 的 `【反馈】` 日志记录机制，用户对当日推荐论文的方法论点评会被自动提取并转化为次日 `argo` 的查询扩展规则与 `claude-paper` 的筛选权重。

### 功能三：南洋理工大学NTU EAI新录取结果全网监测与主动报告

与每日固定在 21:00 触发的定时任务不同，“盯着 NTU EAI 在互联网或者中介案例库里出现的新录取结果，一旦有新录取结果就主动报告，并根据反馈调整下一次推荐偏好”要求智能体扮演全天候异步驻留的主动服务哨兵（Proactive Service Sentinel）。在真实互联网环境中，南洋理工大学（NTU）人工智能相关项目（EAI）的录取报喜、三维背景（BG）分享与中介战报高度碎片化地散落在小红书、一亩三分地、寄托天下、知乎、Reddit 以及各大留学中介网页案例库中。环境信号具有显著的不完整性与高噪声（例如往年旧案例被中介重发引流、同名项目缩写混淆、或发帖者仅为“求定位/等结果”而非真正收到 Offer）。如果智能体稍有风吹草动就立刻打断用户，会迅速引发警报疲劳与信任崩塌；反之若漏掉关键批次的放榜动态，则丧失哨兵价值。

2026年9月3日发表的论文 *Proactive Service Agents: A Unified Decision Framework, Methods, and Evaluation*（`arXiv:2609.03727`，Yan Tang、Tingyu Cao、Yuanbo Tang 等）构建了此类主动服务智能体的统一决策理论与评估框架。该研究指出，主动服务将决策点推向上游（Moves the Decision Upstream），智能体必须从不完整的环境与用户信号中自主推断服务介入时机。可靠的主动报告绝不能仅凭简单的关键词匹配触发，而必须同时满足四项严格准则：校准的边际干预价值（Calibrated Incremental Intervention Value）、可验证的授权边界（Verifiable Authorization）、可恢复的执行状态（Recoverable Execution）以及反事实证据（Counterfactual Evidence）。在 NTU EAI 录取监测场景中，智能体必须通过反事实证据检验（即评估“若不推送此条疑似中介旧闻或背景悬殊案例，用户是否会遭受实质信息损失，以及当前推送的边际信息增益是否大于打扰成本”），仅当确认属于真实新增录取且符合用户关注维度时才触发主动报告，并利用用户对报告案例的反馈（如“忽略海本超高 GPA 案例，重点盯陆本 985/211 跨专业申请的最新录取”）持续重校准边际干预价值估值函数。此外，2026年9月2日提交的 *Monitoring Web Agents Without Internal Signals: Observable Trajectories and Key-Step Supervision*（`arXiv:2609.02057`）进一步提供了基于可观测网页轨迹与关键步监督的早停干预机制，保障长周期网页监测在固定误报预算下的跨站点泛化能力。

由于小红书、留学论坛及部分中介案例库存在严格的防爬校验与登录态限制，单纯的无状态 HTTP 抓取工具无法胜任。DeepSeek Harness 生态中最成熟的解决方案是官方精选的真实浏览器桥接插件 `titanwings/dsh-better-browser`（或自包含 Playwright Chromium 与 OpenCLI 9 大交互工具的 `anweat/dsh-browser`），配合多平台即时通讯主动推送网关 `dsh-im-hub` 与 `plugin-notify`。`titanwings/dsh-better-browser` 通过 Kimi WebBridge 直接驱动用户的真实浏览器实例，完整复用已登录的社区 Cookie 会话，支持自动导航、DOM 快照提取、交互点击、截图取证、网络数据包检查（Network Inspection）与多标签页管理。结合后台循环插件 `dsh-loop`，智能体按预设间隔静默巡检目标论坛与中介案例库的最新动态，通过比对页面快照哈希与发帖时间戳剔除旧闻；当检测到附带录取信截图的新增战报时，调用视觉工具核验入学季与专业名称，确认无误后立即通过 `dsh-im-hub`（支持飞书 Feishu、企业微信 WeCom、Telegram 机器人双工会话）或 `plugin-notify`（Webhook 与桌面通知）主动向用户手机与桌面端推送结构化录取简报，并将用户在聊天窗口中回复的偏好修正实时同步回主监测回路。

## 认知、记忆与开放式探索层：从碎片化检查点到统一认知世界模型

当个人智能体从单一任务的执行工具演进为长期伴随的数字分身时，系统的核心瓶颈迅速从表层工具调用转移至内部认知与记忆架构。为了支撑涵盖用户身份、动机、目标与方法的全维度长短时记忆补充（功能四）、围绕二次元与计算机技术的开放式自主探索与问题构想（功能五），以及消除长周期推理中的认知幻觉与状态污染（功能十二），2026年9月以来的最新学术研究与 DSH 插件生态共同完成了从“碎片化 Checkpoint 向量库”向“中间件化、全息视图化与可编辑世界模型”的代际跨越。

### 功能四：涵盖用户身份、动机、目标与方法的动态长短时记忆系统

“用户想要做的事情（What）以及用户是什么（Who）、为什么（Why）、怎么做（How）都有长短时记忆系统进行动态补充”这一需求，直指传统单一向量数据库（RAG）作为智能体记忆底座的根本缺陷：将所有历史对话切片无差别地塞入同一个向量空间，既无法区分“瞬时工作上下文（短期记忆）”与“跨会话核心信念（长期记忆）”，也无法区分语义事实（Who/What）、因果决策链（Why）与操作规程（How），最终导致上下文窗口被过期噪声淹没，或者在关键决策时遗漏前置约束。

2026年9月25日至26日连续发表的两篇重磅论文从认知中间件解耦与异构记忆动态路由两个维度彻底解决了该问题。首先是 IBM Research 于 2026年9月25日提交并被 Middleware 2026 录用的论文 *Memory as Middleware for Self-Improving AI Agents*（`arXiv:2609.32091`，K. R. Jayaram 等 7 位学者）。该文指出，当前主流智能体普遍采用“定制化手工作坊记忆（Bespoke Memory）”，将检索、持久化与冲突消解逻辑硬编码在单个智能体内部并绑定单一存储引擎。作者提出了参考实现架构 ALTK-Evolve，将记忆抽离为具备“捕获（Capture）→ 提取（Extract）→ 泛化整合（Consolidate）→ 发布（Publish）”多步原子事务语义的独立可插拔中间件层，并严格按认知功能划分为三大命名空间：语义记忆（Semantic Memory，存储关于用户身份属性 Who、项目与环境稳定事实 What 的长期知识）、情景记忆（Episodic Memory，记录特定会话中的决策轨迹、错误原因、修复过程与结果，回答为什么这样做 Why）以及程序性记忆（Procedural Memory，通过先泛化再整合 Generalize-then-consolidate 的准则，提炼出如何执行重复性操作的可复用规程 How，并在操作层级而非字面文本层级检测重复与矛盾）。紧接着在 2026年9月26日提交的论文 *MemAgent: Learning to Manage Heterogeneous Memory Providers for LLM Agents*（`arXiv:2609.32521`）则进一步将长短时异构记忆管理形式化为一个动态路由问题：由专门训练的记忆路由智能体在每个推理步动态决定应当从哪个长期记忆提供者（Memory Provider）检索、是否注入短期记忆（Short-term Memory）以及如何按预算裁剪上下文。在 GAIA、WebWalkerQA 和 xBench-DS 三大复杂长程基准测试上，`MemAgent` 将平均准确率大幅提升了 10.0%，全面超越所有单一记忆方法，同时将平均任务执行步数减少了 12%，而路由本身的算力开销低于 0.3%。此外，针对端侧个性化图存储的 *HGP*（`arXiv:2610.10071`）与软化硬提示记忆的 *HasMem*（`arXiv:2609.30797`）亦为长短时记忆补充提供了有益的算法支撑。

在 DeepSeek Harness 生态中，实现 What、Who、Why、How 全维度动态长短时记忆补充的最成熟插件方案是 `omdsh-dev/dsh-mnemon`（480+ Stars，合并 219 个 PR，Composio 与社区首推的视图化三层记忆系统）配合 `dsh-statecore` 与 `csyangwen/dsh-memory-evolve`（此外社区还有获 2.2K 下载量的 `TencentDB Agent Memory`、`dsh-vault` 1.4K、基于 SQLite 与 Markdown 双镜像及 autoDream 自我巩固的 `dsh-mneme`、以及 `@openviking/dsh-memory-plugin`）。`omdsh-dev/dsh-mnemon` 摒弃了单一数据库堆砌模式，原生提供开箱即用的三层存储架构（Three-Tier Memory）：第一层为运行时热记忆（Runtime Hot Memory / 短期记忆），让当前用户偏好与工作事实常驻活跃上下文；第二层为项目文档（Project Documents）；第三层为长期记忆空间（Memory Spaces），仅在问题需要时按需检索长期证据。每个回复下方均提供透明的“本轮记忆栏（Turn Memory Bar）”，用户可一键点击大脑图标将新事实交由任务 Agent 去重提炼并写入对应的工作记忆、个人档案或记忆空间。与此同时，`dsh-statecore` 在每个推理步前（pre-step，含上下文压缩后）自动注入受预算控制的记忆摘要，并直接暴露 5 个原生工具：`remember`（记下要做的事 What）、`recall`（检索怎么做 How）、`facts`（查询用户与环境是什么 Who/What）、`why`（通过证据链与替代链 Evidence & Supersession Chains 追溯为什么做出某项决策 Why）以及 `forget`（主动淘汰过期记忆）。若再叠加 `csyangwen/dsh-memory-evolve` 的五轨记忆（用户档案轨、全局事实轨、Git 分支感知的项目关键记忆轨、每日与项目日志轨、四轨待办与后台技能进化轨），即可实现零核心修改的全维度长短时记忆闭环。

### 功能五：围绕二次元与计算机技术的开放式自主探索、问题构想与主动汇报

“用户偏好二次元和计算机技术这块，需要自主发现新事物，构想新事物，做新事情，发现新问题，解决新问题，调研等，有什么重要结果主动向用户报告”这一需求，要求智能体实现从“指令驱动（Instruction-driven）”向“内驱力与好奇心驱动（Proactivity & Curiosity-driven）”的质变。在没有人类明确指令的空闲时段，智能体如何主动将算力转化为有价值的跨界探索与工程实践，同时避免沦为制造垃圾信息的噪音源，是主动式智能体（Proactive Agents）研究的核心命题。

2026年9月29日发表的论文 *Foundations of Proactive Agents: Principles, Technical Layers, and Proactivity-Gym*（`arXiv:2609.37267`，Jio Oh 等 5 位学者）系统奠定了这一领域的理论基石与技术分层。论文指出，主动式大语言模型智能体的核心价值在于能够将后台空闲算力（Idle Compute）在用户开口提问之前转化为实质性的支持工作（如前置文献调研、新工具构想、潜在问题诊断与原型验证）。然而，作者通过实证研究揭示了一个深刻的悖论：即便智能体在后台自主完成的调研或代码构建在客观上是正确的，如果误判了用户当前的认知上下文，或者不加节制地将半成品推给用户，也会给用户造成沉重的“审查负担（Review Burden）”，进而导致用户信任度下降。为此，`Proactivity-Gym` 提出了有用工作产出（Useful Work）、后台算力分配（Compute Allocation）与动态演进的用户信任（Evolving User Trust）三元联合设计准则：智能体在后台利用廉价算力自主执行“发现新事物 → 构想新方案 → 动手做新事情 → 发现并解决衍生新问题”的多步循环，但必须通过严格的内部完备性与重要性门控，仅在取得经验证的实质性重要成果时才主动向用户呈交高价值报告。

在 DeepSeek Harness 生态中，能够深度融合“二次元 + 计算机技术”复合极客画像，并真正实现自主构想、动手实践与主动发起对话汇报的黄金插件组合是 `whiteguo233/OpenBiliClaw`（3.4k Stars，及其客户端插件 `dsh-openbiliclaw`） 配合 `william-jin-cmu/dsh-evolve`。`OpenBiliClaw` 的核心设计哲学正是“根据理解主动探索，而非被动匹配”。它一方面连接二次元核心阵地（B站、Bangumi、小红书、抖音、X），另一方面连接计算机技术核心社区（GitHub、Linux.do、V2EX、Reddit、知乎与开放 Web），通过五层灵魂画像（Event → Preference → Awareness → Insight → Soul）持续推断用户的认知风格与深层精神需求。极具创新性的是其“兴趣探测（Interest Probes）”机制：系统利用心理学桥接逻辑，主动猜测并构想用户在“二次元 × 计算机技术”交叉地带可能热爱但尚未涉足的新事物（例如结合动漫角色视觉渲染的新型神经着色器项目、二次元风格终端 UI 组件或开源 AI 角色语音合成算法），生成投机兴趣假设（Speculative-interest Hypothesis）并通过 `interest.probe` 事件主动找用户探讨验证；猜中则升级为正式长期探索方向，猜错则静默退场。更进一步，由于传统工具属于被动拉取（Pull 模式），在定义上无法主动发起对话，而挂载 `william-jin-cmu/dsh-evolve` 后，智能体可以利用 `inject: ['agents']` 服务编写并热挂载后台自驱探索插件：在后台自主调用 GitHub 与搜索工具调研新发现的开源项目、在本地沙箱中构建新实验或编写新的 DSH 桌面伴侣插件（如社区高达 2.5k Stars 的鲸鱼娘皮肤 `Small-tailqwq/dsh-deep-whale` 或 `whale-girl` 交互桌宠）、自主排查并修复编译与运行中的新问题，最后通过插件定时器或事件钩子直接对空闲的主会话发送 `send` 唤醒指令，在用户未发一言的情况下主动发起新回合汇报重要探索成果。

### 功能十二：认知与记忆层跃迁——从碎片化Checkpoint到统一认知世界模型

在长周期复杂任务中，即便为智能体挂载了常规向量数据库与周期性文件快照（Checkpoints），智能体依然会在数十个推理回合后出现决策退化与方向迷失。其根本原因在于，碎片化的历史记录无法阻止错误假设在上下文中的累积传染。如何将智能体的认知与记忆层从零散的“碎片化 Checkpoint”升级为具有前瞻因果推演与自我纠错能力的“统一认知世界模型（Unified Cognitive World Model）”，是 2026 年下半年认知架构演进的核心焦点。

2026年9月23日由中国人民大学高瓴人工智能学院（Shuang Sun、Guoxin Chen、Wayne Xin Zhao、Hongteng Xu、Ji-Rong Wen 等 9 位学者）发表的标杆论文 *Agent-Editing World Model: Rethinking World Modeling for LLM Agents*（`arXiv:2609.28416`，简称 AEWM）完成了这一领域的理论范式重构。论文指出，过往的语言智能体世界模型盲目沿用了具身智能与视频生成中的“环境中心目标（Environment-centered Objective）”，即试图预测执行某个动作后外部工具会返回什么具体观测结果（例如预测搜索引擎返回的网页文本或终端输出的报错日志）。然而在开放数字环境中，工具返回观测具有极高的信息熵且强依赖于实时外部状态，强行用大模型模拟预测环境观测不仅困难，反而会引入虚构证据（Fabricated Evidence）。作者通过对长程轨迹的深度诊断，揭示了导致智能体崩溃的真正症结——“任务状态污染（Task-State Contamination）”：智能体在探索未知环境时，往往会将未经证实的假设当成既定事实、在收到矛盾的环境反馈后仍固守过期计划、或将局部进展误判为全局完成（例如继续追逐已被证伪的搜索方向，或在未经验证的代码上继续堆砌修改），这些内部认知错误一旦留在历史记录中，就会通过局部看似合理的动作不断复利放大。为此，AEWM 将世界建模的目标彻底转向“预测智能体自身的内部认知解释与动作如何影响未来的任务进展，并在执行前主动编辑修正内部认知状态”。AEWM 包含两大核心机制：其一是前瞻动作评判器（Action Judge），仅基于当前可见历史 $h_t$ 与拟议的推理及动作 $(\hat{r}_t, \hat{a}_t)$，在动作执行前预测其下游贡献并分类为关键推进（Critical）、有效探索（Exploratory）或噪声污染（Noisy），在涵盖 Search、Terminal 与 SWE 的 3,000 个决策基准上取得了 70.5% 的 Macro-F1，超越最强前沿基线达 10.6 个百分点；其二是状态修订与推理集成机制（State Revision & EditAct），一旦拟议动作被判定为受污染的 `Noisy` 状态，State Revision 模块立即在执行前介入，将受污染的内部推理与动作重构为 $(\tilde{r}_t, \tilde{a}_t)$，驱使智能体通过与真实环境交互去搜寻缺失证据而非依赖错误假设。在 6 大基准与 3 种骨干模型上，EditAct 将平均任务得分提升了 3.2 至 6.7 分，基于验证轨迹的拒绝采样微调（AEWM-RFT）亦比 Self-RFT 提升 2.2 至 2.6 分。此外，2026年9月29日发表的 *Lucid Dreaming for World Models: Learning to Doubt Imagination and Decide by Trust*（`arXiv:2609.37156`，LucidWM）进一步提出了让世界模型学会怀疑内部想象并依据信任度决策的互补机制。

在 DeepSeek Harness 中，将认知与记忆层从“碎片化 Checkpoint”升级为“统一认知世界模型”的最成熟工程实现，是由 `omdsh-dev` 团队构建的 `dsh-mnemon`（480+ Stars）及其全息世界状态子模块 `dsh-mnemon-provider-holographic`（版本 `v0.5.6`）与 `dsh-statecore`。`dsh-mnemon-provider-holographic` 作为长期记忆空间的核心适配器，不再保存碎片化的文本块，而是构建了一套带有信任度元数据（Trust Metadata）、实体节点（Entities）与关联证据链（Related Evidence）的本地全息结构化事实图谱（Holographic Structured-Fact Storage）。在此基础上，`dsh-mnemon` 将运行时热上下文、项目文档与跨会话全息事实通过 `Source + Strategy + Provider` 管道，在每一轮推理前动态合成为不可变的逐轮认知视图（Immutable Per-Turn View）。当环境反馈推翻早期假设时，系统通过 `dsh-statecore` 的替代链（Supersession Chains）显式标记旧事实已被新证据取代；而在跨设备或多智能体并发修改同一主题导致认知分歧时，`dsh-mnemon` 的记忆调解器（Memory Reconciliation / Reconcile）会并列保留冲突表述并生成一份结构化的认知调解计划（Pending Proposal），在验证后按原子操作粒度合并修正，从而在运行时底座层面彻底根除了任务状态污染，建立起全局自洽的统一认知世界模型。

## 运行时控制、安全治理与自进化层：长周期循环、多智能体信息系统与权重冻结演化

个人智能体若要脱离人类高频看管，独立承担长周期工程与科研任务，必须在运行时控制层解决四大硬核系统难题：如何在不牺牲安全性的前提下消除人类审批疲劳（功能六）、如何跨越上下文窗口极限持续推进长程目标（功能九）、如何将本地多智能体设计为不崩溃的严谨信息系统（功能十），以及如何在冻结模型权重的条件下实现运行时自我优化与能力泛化（功能十一）。

### 功能六：关键事项主动请求授权与常规事务自主行动的风险门控机制

“只有非常关键的需要用户授权的事项主动向用户要求授权，一般事物自主行动”是平衡个人智能体自治效率与系统底线安全的核心支点。传统的安全沙箱往往采取僵化的静态关键词黑名单策略（例如只要命令中包含删除或网络请求指令就一律弹窗阻断），导致用户在高频点击“确认允许”后产生严重的审批疲劳（Approval Fatigue），或者干脆开启全权限裸奔模式；而部分依赖轻量级安全分类器的方法则缺乏对多步操作链条上下文的因果理解。

2026年9月23日发表并被 EMNLP 2026 录用的论文 *PASTABench: Proactive Assessment of Sequential Trajectories for Agent Safety*（`arXiv:2609.28197`，Jiapeng Sun 等 7 位学者）深刻揭示了传统智能体安全拦截中的“词汇过拟合（Lexical Overfitting）”现象。研究证明，许多在常规安全基准上表现优异的守护模型并非真正理解操作序列的潜在破坏性，而是对表层危险词汇过度敏感（Keyword Hypersensitivity）：这不仅导致大量无害的常规事务被误拦，更致命的是，一旦多步攻击或高危操作序列中的敏感词汇被中性化改写（Hazard Vocabulary Neutralized），这些模型的安全预判能力便会瞬间瓦解。`PASTABench` 由此确立了面向序列轨迹的主动安全评估范式，要求门控系统结合完整历史轨迹评估动作的真实语义后果与操作可逆性。与此同时，2026年9月19日提交的 *MATE: Policy-Aware Security Auditing for Mobile Agents via Synthesis-Driven Trajectory Learning*（`arXiv:2609.22724`）通过合成驱动的轨迹学习，在真实设备上实现了超过 95% 的细粒度策略感知安全审计准确率（超越既有方法逾 20 个百分点）；而 2026年9月30日提交的 *Speculative Safety Honeypot*（`arXiv:2609.39549`）则进一步引入投机安全蜜罐机制，显著延长了对复杂多轮时序风险的预警提前量。

在 DeepSeek Harness 生态中，实现“常规可逆事务零打扰自主放行、关键不可逆事项强制人工授权”最成熟、星标与安全认证等级最高的插件是 `moon09300731/dsh-approval-gate`（91 Stars，17 Forks，已通过 `dsh.so` 最高等级的 L5 运行时沙箱安全验证，持续适配至 `dsh 0.1.6`）。此外，社区亦有 `arrow949/dsh-turn-approval`（单次任务内同类高权限请求临时自动放行，任务结束自动失效）与 `cdxiaodong/dsh-guardian` 作为辅助补充。`dsh-approval-gate` 构建了一条严密的五级故障安全（Fail-safe）判定管道（`DENY → 白名单 → denyRules → Flash 语义预判 → 确认制学习`）。每次智能体请求跨出工作区沙箱执行写入或终端命令时，轻量级 Flash 模型会实时对操作的可逆性进行语义预判（输出 `SAFE` 或 `RISKY:<类别>`）：常规可回补操作被直接判定为安全并自动放行，仅在输入框上方显示柔和的绿色非阻塞提示；而针对删除操作（Delete）、凭据读取（Credentials）、远程与生产环境操作（Remote/Production）、系统级路径修改（System Paths）以及批量不可逆修改（Batch Irreversible）这五类核心硬风险，系统采取绝对熔断机制，永远主动弹窗要求用户人工确认授权，且绝不计入自动学习计数。对于非硬风险的特殊操作，用户手动确认 $N-1$ 次后，插件会生成带有操作指纹（Operation Fingerprint）的沉淀规则；即便后续命令措辞发生变化，Flash 模型也能对照确认样本进行语义同类验证并自动放行。更具工程价值的是其 `v0.5.0+` 引入的基于工具调用参数追踪的会话级精确快照管理：在轨迹右侧的「审批」视图中，用户可随时点击查看任何自动放行或人工审批文件的双行号 Unified Diff（绿底新增、红底删除），并可一键点击「撤销此改动」令智能体严格按审批前快照恢复文件，为一般事务的高度自治提供了坚实的可逆回滚保障。

### 功能九：Loop Goal等长时间运行机制与跨上下文边界状态续接

当智能体执行长达数小时乃至数天的 `Loop Goal`（例如全量重构复杂代码仓库、自动化运行多轮机器学习消融实验或持续追踪修复回归测试）时，系统面临两大结构性失效模式：其一是活跃上下文窗口溢出（Context Overflow），传统的黑盒摘要压缩（Compaction）往往在数次上下文交替后丢失关键的报错证据、已排除假设与中间变量，导致智能体在长程循环中重蹈覆辙；其二是长序列生成中的执行惰性，即模型在回合中仅用自然语言叙述下一步打算执行的操作，却未发出实际的 Tool Call，导致事件循环意外终止。

2026年9月28日由京东探索研究院（Lirui Luo、Kelong Mao、Heming Xia、Cong Fang 等 13 位学者）发表的论文 *Coding Agent Memory Post-training: Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via Reinforcement Learning*（`arXiv:2609.34422`，简称 CAMG-RL）为长周期持续运行机制提供了突破性的理论与实证方案。论文提出了核心论断：“文件不仅仅是工作产物，文件本身就是长程记忆（Files are not just artifacts. They are memory.）”。`CAMG-RL` 敏锐地利用了代码预训练模型天生精通 Shell 命令与工作区文件读写（创建、检索、修订文本文件）的先验能力，在一个共享持久化工作区的异步 PPO 强化学习循环中训练任务执行策略：当活跃上下文窗口即将达到容量边界触发替换（Context Replacement）前，策略不再依赖外部黑盒摘要器，而是自主将当前任务目标（`objective`）、已获取的核心证据（`evidence`）、已验证的测试结果（`tested`）以及下一步具体行动计划（`next`）显式写入工作区持久化续接文件 `.agent_memory/CONTINUATION.md` 中；上下文重置后，新回合仅接收该续接文件的路径，并通过标准的 `cat` 或文件读取动作将完整推理状态恢复至新上下文中。由于训练过程中不设人为的独立记忆奖励，仅以最终长程任务的成败作为强化学习信号，策略学会了精准保留真正有助于任务成功的最小完备状态。实证数据表明，在涵盖电商决策（WebShop，成功率 97.1%）、深度研究（LiteResearcher，55.5%）、自动化机器学习研究（OpenMLE，38.3%）与软件工程编码（SWE-smith，26.6%）的四大长程基准上，仅 4B 参数规模的 `CAMG-RL` 模型即可将最末训练季度的完整记忆链比例提升至 20.9%，平均任务成功率达到 54.4%（超越 CompactionRL 基线 6.4 个百分点），并在 SWE-bench Verified（+15.8% 外部迁移增益）与 MLE-bench Lite 上展现出与 Qwen3.5-35B-A3B 及 122B-A10B 大模型相媲美的长程持久执行能力。

在 DeepSeek Harness 生态中，支撑 `Loop Goal` 长时间稳定运行的工业级方案由四个紧密咬合的插件共同构成：`dsh-loop`、`dsh-loop-continue`、`carbide4826/dsh-loop-guard`（辅以 `ICCuse/dsh-pain-point-check`）以及 `fakechris/dsh-harness-ops`。`dsh-loop` 为系统注入 `/loop` 命令、`loop` 调度工具与底部实时活动状态栏，配合 `dsh-task-status` 与 `dsh-ui-progress` 实时展示后台任务进度与输出流尾部（Output Tail）。针对模型在长循环中“只说不做”导致的循环中断，`dsh-loop-continue` 通过监听 `agent/settled` 回合结束事件，在检测到模型仅输出动作叙述而未发起工具调用时自动注入续接指令，强制维持目标循环运转。针对长周期运行中可能出现的死循环与同方向盲目重试，`carbide4826/dsh-loop-guard` 与 `ICCuse/dsh-pain-point-check` 构建了强制痛点熔断机制：一旦同一问题连续两个实验周期未能收敛，插件立即注入“痛点三问”并强行拦截一切非调查类（Non-investigative）工具调用，逼迫智能体先读取日志查明根因并写出分析，防止无人值守时无意义地空耗 Token。最后，在进程高可用层面，`fakechris/dsh-harness-ops` 提供了 10 秒级守护进程（Watchdog），当 DSH Web 或 Agent 进程因系统负载异常中断时，10 秒内自动重启服务并无缝续接被打断的回合，配合每日快照 A/B 双槽原子轮换与 `dsh-doctor` 一键诊断修复，确保数日级别的 `Loop Goal` 稳如磐石。

### 功能十：将多Agent作为严谨信息系统设计，实现本地多智能体不崩溃长期协作

“把多 Agent 当成严谨的信息系统来设计，实现本地多智能体不崩溃地长期协作”切中了当前开源多智能体框架的最大软肋。绝大多数早期多智能体工具仅将 Multi-Agent 视为“多个扮演不同角色的 Prompt 在同一个群聊中自由对话”，缺乏分布式信息系统所必需的事务隔离、状态有效性治理、内存预算编排与存储帧完整性校验。在本地长期运行复杂协作任务时，这种松散架构极易因“过期派生结论污染”引发逻辑雪崩，或因本地统一内存溢出与会话文件撕裂而直接崩溃。

2026年9月27日发表的 41 页系统级长文 *TRACE: Governing Memory Validity in Evolving Multi-Agent Systems*（`arXiv:2609.33517`）首次将多智能体长期协作纳入严谨的信息系统数据有效性治理（Memory Validity Governance）框架。论文指出，在动态演进的多智能体系统中，当某个智能体更新了底层事实或推翻了某项前置设计时，共享记忆库中不仅直接描述旧事实的记录会失效（STALE Type I），更隐蔽且致命的是，其他子智能体在此前协作轮次中基于该旧事实推导出的二级派生结论与计划（STALE Type II）依然以“有效状态”残留在共享上下文中，导致后续接力的智能体在不知情中基于过期前提继续施工，最终引发系统级逻辑崩溃。`TRACE` 通过构建严密的跨智能体记忆溯源依赖图与读写有效性校验协议，实现了对演化多智能体系统中过期派生状态的精准识别与级联治理：在极具挑战性的 STALE Type II 基准测试中，`TRACE` 在仅消耗约 2.3 倍 Token 的条件下，将多智能体协作总体得分在 DeepSeek 基座上大幅提升了 27.5 分（在 Qwen 上提升 22.3 分，在 Gemini 上提升 18.5 分），而若配合写入时整合管道（Write-time Consolidation Pipeline）更能获得进一步的一致性提升。此外，2026年9月18日的 *MACE: Memory-Agent Co-Evolution with Adaptive Memory Graphs for Multi-Agent Systems*（`arXiv:2609.21533`）通过自适应记忆图谱与智能体协同演化在 8 大基准上取得了 81.11% 的平均分（超越最强基线 SAGE 的 78.97%）；2026年9月9日修订并入选 EMNLP 2026 主会的 *Learning What to Retain: Gated-Memory Routing for Efficient Collaboration in Multi-Agent LLM Systems*（`arXiv:2609.00237`）与 *Agentsensus*（`arXiv:2609.32297`）分别通过门控记忆路由和共识压缩共享记忆将多智能体存储膨胀降低了 3.1 倍；而在本地硬件防崩溃层面，2026年10月2日提交的 *EdgeAgent: Orchestrating On-Device LLM inference for End-User Multi-Agent Systems on CPU-GPU Unified Memory Architectures*（`arXiv:2610.03394`）则专门针对本地 CPU-GPU 统一内存架构设计了多智能体推理调度器，从操作系统底层根除了本地多 Agent 并发时的内存踩踏与 OOM 崩溃。

在 DeepSeek Harness 生态中，得益于其可将内部子会话乃至外部异构代理（Claude Code、Codex、Kimi、Grok、Hermes）统一封装为 Cordis 插件的架构优势，将本地多智能体构建为严谨信息系统的最佳插件组合是 `csyangwen/dsh-memory-evolve`（COI 协同调度、房间广播与四级独立评审系统） 配合 `plugin-team-board`、`dsh-preset-flash-director`、`vibeinging/dsh-agent-budget` 与 `omdsh-dev/dsh-session-health`。在信息流与任务总线设计上，`plugin-team-board` 基于 Cordis 内核服务键（Service Key）提供强一致性的共享多智能体任务看板，而 `csyangwen/dsh-memory-evolve` 的 COI 调度器支持主控智能体一方面 `spawn` 出前端、后端、测试等多个内部子会话拉入共享房间（亦可配合 `kotinder/dsh-roomcomm`），另一方面将耗时专项任务连同当前项目的 Git 分支记忆与截图附件异步派单给外部异构代理在后台独立运行，任务完成后其结果摘要自动沉淀为标准化项目记忆并广播至协同房间，确保所有子智能体遵循统一的工程规范接力作业。在质量控制与防跑偏设计上，系统引入了独立上下文的“会话评审员（Session Advisor）”，遵循四层结构化约束（全局系统提示词、项目约束、会话约束、本次评审会话约束，冲突时越局部越优先），并以 `info`（仅记录）、`nit`（细节建议）、`concern`（值得处理）与 `blocker`（严重阻断，必须立即修复）四级严重度对各智能体的输出进行实时审计，避免无意义的频繁打断。最后，在底层稳定性保障上，`dsh-preset-flash-director` 利用廉价高效的 Flash 模型担任顶层路由导演，结合 `vibeinging/dsh-agent-budget` 对整棵多智能体调用树（Agent Tree）实施严格的 Token 与内存预算硬上限管控，并由 `omdsh-dev/dsh-session-health` 持续对会话文件进行帧级扫描诊断（实时检测并隔离损坏帧、撕裂帧与空会话），从而在本地环境中实现多智能体长期不崩溃的工业级协作。

### 功能十一：保持模型权重不变的Agent自进化与跨场景泛用能力生成

“保持模型权重不变的 Agent 自进化，包括插件、agent loop、上下文等诸多方面的自我优化，以及自进化后的泛用能力”代表了智能体运行时工程的最高形态。在基座大语言模型权重完全冻结（Weight-frozen）的前提下，智能体若要实现真正的能力跃迁而非仅仅在提示词末尾追加几条文本经验，就必须具备在运行时自主编写、挂载、测试、修正乃至卸载自身代码组件（工具、事件循环钩子、上下文压缩器）的元编程能力，并保证这些自生长出的新能力在未来所有会话与跨领域任务中具备可证明的泛用性与稳定性。

2026年10月2日发表的论文 *A Kinetic Theory of the Gated Self-Evolving LLM Agent*（`arXiv:2610.03243`，作者 Haipeng Wang）是一篇直接以生产环境中的 DeepSeek Harness（DSH）插件架构作为研究对象，为其建立严密数学物理理论的里程碑式著作。该研究指出，以往的自进化研究往往将整个智能体视为不可拆解的单一黑盒单元，而在 DeepSeek Harness 这类“一切皆插件”的运行时底座中，门控自进化（Gated Self-Evolution）的本质是智能体在验证门控（Validation Gate）的约束下不断重写其自身技能与插件的闭环过程，其基本演化单元是注册表中的“插件—版本实例（Plugin-Version Instances）”。由于 DSH 插件严格满足置换对称性等四项架构属性，当智能体维护着一个庞大的插件版本群体并在任务流中不断迭代时，该群体的宏观统计行为在数学上精确表现为受外部选择器做功的分子气体，呈现出清晰的流体动力学（Fluid Dynamics）特征。作者在“插件 $\times$ 版本 $\times$ 任务（$\text{plugin} \times \text{version} \times \text{task}$）”三维网格上建立了包含四个算子的动理学主方程（Kinetic Master Equation）：碰撞算子（Collision，刻画不同插件在同一任务中的共激活与协同咬合）、反应算子（Reaction，刻画智能体自主改写代码产生的版本突变）、外场算子（External Field，刻画外部任务环境的选择压力）以及门控算子（Gate，刻画回归测试与验证门控的优胜劣汰）。通过矩层级展开（Moment Hierarchy）将气体动理学转化为流体方程，论文不仅在预注册探针实验中证实了密度门控的群体涨落标度律（Population Fluctuation Scaling，在稀疏编辑密度下不可见，而在三倍编辑密度下按理论预测速率涌现），而且从数学上证明了在修正后的验证门控下，插件群体得分的跨运行离散度随群体规模 $N$ 呈幂律衰减（$\beta < 0$）。这一理论直接解释了为什么基于 DSH 插件架构的权重冻结自进化不会陷入局部退化，而是能够涌现出跨任务、跨会话的强泛用能力。

在 DeepSeek Harness 生态中，将这一理论转化为现实的核心开源插件是由 CMU 研究者开发的 `william-jin-cmu/dsh-evolve`，配合元认知自进化引擎 `dsh-tool-meta`、代码转技能工具 `Code2Skill`、失败错因自纠插件 `Areium/dsh-fail-logger` 以及上下文自优化插件 `Sev7eEn7/dsh-sieve` 与 `billion-context-dsh`。`william-jin-cmu/dsh-evolve` 充分利用了 DSH 每个推理步（Step）实时从当前挂载插件重算工具列表（无会话级静态快照限制）以及 Cordis 4 Fiber 可回滚副作用的底层机制，向智能体暴露了 `evolve_add(name, source, description, config)`、`evolve_remove` 与 `evolve_list` 三个核心元工具。在会话过程中，一旦用户的自然语言表述暴露出高频能力缺口（例如跨会话家庭记账、多仓库提交周报汇总、实时汇率换算或私有项目错误码速查），智能体当场编写一段纯 ESM 的 Cordis 插件源码持久化至 `~/.dsh/evolve/*.mjs` 并实时热挂载——新长出的工具在紧接着的下一个 Step 即可被直接调用，不再需要时可逆卸载（自动清理其注册的所有工具、监听器与服务），且在系统重启或开启新会话时自动恢复挂载，泛用于后续所有任务。更为深刻的是，`dsh-evolve` 实现了对 Agent Loop 本身与系统行为的自进化：面对“每次干完活自动记工作日志”或“控制回复长度并在超限时逼迫重写”这类被动工具（Pull 模式）必然失败的需求，智能体现场写出的插件不注册任何工具，而是直接挂载常驻 System Prompt 规则、`agent/step` 与 `agent/settled` 事件循环钩子以及主动唤醒定时器，将自动化逻辑彻底从模型的推理决策空间下沉至确定性的运行时层（实现零 Token 消耗的自动日志记录）。在端到端实测中，智能体不仅能自主编写回归测试发现自己所写插件中的 `--since` 日期边界 Bug 并通过同名 `evolve_add` 热升级为 `rev 2` 修复版，还能让新进化出的“早间主动问候插件”自动检索并调用此前进化出的“天气插件、家庭纪念日插件与账本插件”，形成多插件相互咬合的自演进有机体。与此同时，`Areium/dsh-fail-logger` 自动拦截并统计全模式下工具调用的失败错因写入 Skill，实现“越用越少错”；而 `Sev7eEn7/dsh-sieve` 与 `billion-context-dsh` 则赋予模型自主修剪上下文、过滤冗长工具输出与渐进式技能披露的能力，在离线回放基准中直接将上下文负载缩减了 36%。

## 交互模态与全域行动层：移动端原生体验、全双工实时语音与物理数字全域操纵

最后三个功能需求指向智能体与人类及外部世界交互的终极形态：打破桌面终端的物理束缚，在智能手机端外出场景下实现与电脑端同级的流畅运行与独立可玩性（功能七）；打破文字输入与半双工对讲机式的交互隔阂，实现支持随时自然打断的全双工实时语音对话（功能八）；打破纯数字代码沙箱的边界，实现从复杂数字 GUI 与云端 SaaS 到物理硬件设备的全域操纵（功能十三）。

### 功能七：手机端与电脑端同级流畅运行，在外独立畅玩Agent的全设备原生架构

“用户在手机端也能像在电脑端一样流畅运行，不仅仅是手机操控电脑，在外面也能爽玩 agent 和做各种事情”这一需求，要求彻底超越传统的“远程桌面投屏”或“简陋移动端网页壳”思维。当用户离开家庭或办公室局域网、甚至在电脑完全关机的情况下，手机端不仅需要作为能够远程调度云端或家中宿主的控制平面，更需要具备独立运行完整 Agent 工作区、直接操纵手机本地文件与应用界面、并在手机退至后台时持续干活的原生能力。

2026年10月6日发表的论文 *nanoMuse: An Open-Source Personal Agent for Every Device You Own*（`arXiv:2610.08699`，作者 Guangyi Liu、Yong Liu、Jiangning Zhang，以 GPL-3.0 协议开源）正式确立了“单一智能体跨用户拥有的每一台设备原生驻留（One Agent on Every Device a Person Owns）”的系统范式。论文指出，2011 年的早期语音助手回答完问题即陷入被动等待，2023 年的初代智能体执行完单次指令即宣告终止，而新一代个人智能体必须是一个横跨手机与电脑、拥有统一记忆与身份的常驻伙伴。`nanoMuse` 在智能手机端直接接管屏幕视觉感知与触控操作（Hands on the phone's screen），支持在移动端 App 关闭或退至后台时继续推進长程任务，并通过可选的轻量级状态中继（Lightweight Relay）在手机与电脑之间实时同步对话流与设备在线状态（Device Presence），同时严格保证用户的敏感私有文件与产物仅保存在本地设备而不经过中继服务器留存。此外，为解决移动端在复杂长程任务中的算力与延迟瓶颈，2026年10月4日提交的 *Sibyl: An Efficient Small-large Model Collaboration Framework for Long-horizon Tasks*（`arXiv:2610.05383`）提出了端侧轻量化小模型（SLM）与大模型高效协同架构；2026年10月8日提交的 *DeltaReplay: Task-Relative Memory Reuse for Mobile GUI Agents*（`arXiv:2610.11707`）与 2026年10月6日的 *Can Agents Work for Everyone?*（`arXiv:2610.07972`）则通过任务相对记忆复用机制，大幅提升了移动端 GUI 智能体在个性化手机界面上的跨应用执行速度与可靠性。

在 DeepSeek Harness 生态中，社区围绕“在外用手机也能像电脑端一样爽玩 Agent”构建了三套成熟度极高的互补方案，均已收录于 DSHub 经过源码级安全审查的官方应用目录。第一套是专为移动端独立运行打造的本地优先移动工作空间 `ZSeven-W/rish-app`（Experimental local-first mobile agent workspace for iOS and Android）：它并非远程遥控器，而是直接在 iOS 与 Android 手机本地运行完整 Agent 工作区，支持在手机端直接配置模型连接、读写手机本地文件、编写与运行代码以及执行移动端自动化任务，让用户在户外完全脱离电脑也能畅玩全功能 Agent。第二套是跨设备统一控制平面 `d4551/DeepTail`（覆盖 Desktop、iOS 与 Android 的多宿主会话控制中心） 与 `whiteguo233/OpenBiliClaw-mobile`（基于 Flutter 构建的 Android 签名 APK 与 iOS 原生 IPA 客户端）：`OpenBiliClaw-mobile` 将个性化推荐、苏格拉底式对话、五层灵魂画像、收藏夹与 30 天历史完整装进手机原生 App，并通过内置 Go 1.26.6 编译的 `tailnet` 私网辅助模块（无需在电脑或手机全局安装配置系统级 Tailscale），使手机在户外蜂窝网络下也能通过点对点加密私网无缝直连家中后端的 SQLite 数据库与 Agent Bridge 工具链。第三套则是全功能移动端 Web 工作台套装 `zhu1090093659/dsh-web-ui` 配合 `Leon0555/dsh-lan-access`：`dsh-web-ui` 内置了专门针对手机触控优化的“远程移动端 UI（Mobile Remote Access）”，将任务看板、Git 提交图谱、SSH 终端、实时 Token 消耗统计、图像工具与交互式桌面宠物（如随 Agent 工作、等待、报错、完成状态实时变换动画的 `minybear/DeepSeek-Harness-Pet` 或离线内置 18 款摸鱼小游戏的 `lhh010/dsh-minigames`）悉数浓缩至手机端，实现与桌面端毫无二致的流畅操作体验。

### 功能八：全双工语音实时对话与低延迟语义打断机制

“全双工语音实时对话”要求智能体彻底摆脱传统“用户说完按键发送 → 等待转写与推理 → 机器播报期间无法插话”的半双工对讲机模式，实现在流式语音播报的同时保持毫秒级双工听觉监听（Listen while Speaking），精准区分用户的背景杂音、善意附和（Backchanneling）与真实打断意图（True Barge-in），并在工具调用期间隐藏等待延迟。

2026年9月下旬至10月初发表的四篇紧密关联的语音智能体论文，从通信架构、快慢双系统协调、流式状态机与工具延迟隐藏四个角度攻克了全双工实时对话的核心瓶颈。首先，2026年9月27日提交（投递 ICASSP 2027）的论文 *Context Spanning: A Communication Framework for Full-Duplex Speech Models and External LLM Backends*（`arXiv:2609.33443`，Seonghyeon Go 等）解决了端到端全双工语音模型“反应快但推理与工具调用智商不足”的结构性矛盾，提出了一套跨模态上下文跨越（Context Spanning）通信框架，能够将外部强推理大语言模型后端及工具执行结果实时、直接地注入正在流式运行的全双工语音模型内部，完美契合了 DeepSeek Harness 将前端语音流插件与后端 DeepSeek-V4 推理引擎解耦的架构设计。其次，2026年9月28日由清华大学与字节跳动语音团队（Wenyi Yu、Chao Zhang 等）发表的 *SALMONN-duo: Adaptive Dual-System Coordination for Full-Duplex Voice Agents*（`arXiv:2609.34247`）构建了快慢双系统自适应协调机制，由快系统维持毫秒级全双工对话流与自然话轮响应，由慢系统异步处理深度逻辑推理。再次，在因果话轮转换与延迟压缩方面，2026年9月17日提交的 *Voice-Light: A Full-Duplex Cascaded Voice Agent with Causal Turn-Taking and Speculative Generation*（`arXiv:2609.20995`） 与 2026年10月6日提交的 *Hiding Tool Latency in On-Device Cascaded Voice Agent through Speculative Execution*（`arXiv:2610.07641`） 利用因果话轮预测与投机执行（Speculative Execution），在用户话音未落或后台工具尚在执行时提前流式生成过渡语音，在真实 Android 语音助手实测中将首字音频延迟（Time-to-First-Audio）中位数从 5.79 秒压缩至 4.60 秒，标准差从 3.49 秒降至 2.81 秒；而 *TurnFSM*（`arXiv:2609.04240`）与全双工合成底座研究（`arXiv:2609.28806`）则通过内化状态机逻辑，将系统话轮占用的帧级预测精确率从 0.46 大幅提升至 0.88，帧级 Floor F1 提升至 0.962（若在手机端侧运行，配合 2026年9月25日提交的 `arXiv:2609.30846` *I-Parakeet* 全整数量化 NPU 语音识别，更可在手机高通 NPU 上实现 0.048 实时率、比 CPU 快 7.5 倍且 WER 仅 4.97% 的极速听觉感知）。

在 DeepSeek Harness 生态中，实现全双工语音实时对话最成熟的代表性插件是社区开源的本地全双工语音插件 `dsh-voice`（收录于官方 GitHub Discussions `#2524` 及 `GooDAnDReaDY/dsh-voice`） 与 `Zhangbo-cn/dsh-voice-input-plugin`。`dsh-voice` 在本地集成了高速多语言富文本语音识别引擎 SenseVoice ASR，无需消耗任何外部云端语音 API Key 即可实现免提实时流式听写（Hands-free real-time streaming dictation），并能够根据人类自然的呼吸停顿自动切分语句（Segmented on natural breath pauses）送入 DSH 事件流。最关键的是，该插件实现了真正的全双工打断（True Barge-in）：当智能体正在通过神经 TTS 流式播报回答时，本地音频管道持续进行语义语音活动监测，一旦用户开口插话提问或纠正，系统立即截断当前 TTS 音频输出与未完成的生成流，无缝切入新回合的实时响应。与此同时，`Zhangbo-cn/dsh-voice-input-plugin` 提供了宿主端 Edge Neural TTS 的“边生成边流式朗读（Streams while the model generates）”能力，并内置了精密的回声暂停机制（Echo-pause during reading）与轻点即停控制，有效防止扬声器播报声引发麦克风自激误触发，为用户提供丝滑顺畅的全双工语音交互体验。

### 功能十三：行动层跃迁——从特定工具调用到物理与数字全域操纵

传统智能体的行动层（Action Layer）往往局限于预定义的少数几个结构化函数（如读写本地代码文件或查询特定数据库）。而“行动层：从特定工具调用到物理与数字全域操纵”则要求智能体跨越数字软件边界与物理硬件鸿沟：在数字域，能够像人类一样直接观察并操控任意无 API 的桌面图形界面（GUI）、浏览器渲染树以及上千种云端 SaaS 应用；在物理域，能够通过实时生成受安全约束的控制代码，直接驱动智能手机传感器、嵌入式测试台架、无人机乃至四足机器狗等物理实体。

2026年10月7日由柏林工业大学（Justus Flerlage、Thorsten Wittkopp、Alexander Acker、Odej Kao）发表并入选 ISoLA 2026（国际形式化方法、验证与确认研讨会）的论文 *Adaptive Code Generation for Controlling Robots*（`arXiv:2610.09588`）为智能体从数字代码生成迈向物理世界闭环操纵奠定了关键方法论。论文指出，直接让大语言模型输出开环动作序列去控制物理硬件，极易因物理环境的不确定性或模型幻觉导致设备失控；作者提出了一套将生成式 AI 锚定在“反应式、受形式化约束的控制闭环（Reactive, Constrained Loop）”中的自适应代码生成架构：智能体根据物理传感器的实时状态反馈，在运行过程中动态编写、验证并热更新底层控制代码，在多个前沿模型基准上证明了无需死板的预定义动作原语，仅凭受约束的自适应代码生成即可实现对物理机器人的高鲁棒性操纵。与此同时，2026年9月28日提交的 *Memory in the Sky: Low-Altitude Question Answering with Multi-Agent Memory Aggregation*（`arXiv:2609.35431`）所提出的 MemCen 系统，成功在真实物理世界中验证了从低空无人机（UAV）全景感知记忆聚合到地面四足机器狗（Robot-dog）环境理解与物理导航的跨载体操纵，在 PMAS 基准上达到了 88.5% 的实测准确率；而 2026年10月7日提交的自动驾驶快慢推理仿真系统 *SIGMA*（`arXiv:2610.09520`，减少 50% 云端冗余交互并缩短 26.2% 完成时间）与防范对抗图像劫持视觉接地（Visual Grounding）的安全性研究 *WebMirage*（`arXiv:2610.09240`）则进一步完善了数字 GUI 与物理操纵的安全边界。

在 DeepSeek Harness 生态中，实现“物理与数字全域操纵”的成熟插件矩阵由四大支柱共同组成：全网星标第一的视觉桥接插件 `liustack/modlens`（4.2k Stars） 与 `@anionex/dsh-vision-toolkit`、macOS 原生桌面操纵插件 `Anionex/dsh-computer-use`（52 Stars）、全能 SaaS 互联插件 `Composio` 以及物理设备操控插件 `dsh-adb`。在数字 GUI 全域操纵方面，`liustack/modlens` 与 `@anionex/dsh-vision-toolkit` 赋予了纯文本 DeepSeek 模型精准的屏幕视觉接地（Visual Grounding）、长截图 OCR、UI 布局还原、像素级差异比对（Pixel Diffs）与 GUI 自动化点击能力；配合 `Anionex/dsh-computer-use` 基于无障碍树（Accessibility-first）的实时界面观测与“过期状态自动拒绝（Stale-state Rejection）”机制，智能体可以直接接管并安全操作电脑上的任何闭源桌面软件。在云端数字生态全域操纵方面，`Composio` 插件将 DeepSeek Harness 一键接入超过 1,500 种主流云端应用（包括 GitHub、Slack、Gmail、Linear、Google Calendar、Discord 等），在底层全自动处理 OAuth 认证、权限作用域（Scopes）与 Token 刷新。而在物理世界与硬件设备操纵方面，收录于 `awesome-DSH-plugin`“生活、设备与物理世界（Life, devices & the physical world）”专区的 `dsh-adb` 插件，将 Android Debug Bridge（ADB）与硬件台架操作（Bench Operations）完整封装为 DSH 工具集，使智能体能够直接通过数据线或无线网络操纵真实的智能手机、嵌入式 Android 开发板、智能家居中控面板及机器人主控板（涵盖实时读取硬件传感器 `logcat` 日志流、编译并动态部署 APK、控制物理外设与执行硬件性能调优）。再结合 `hyqhyq3/dsh-mcp-manager` 接入物联网与 ROS 机器人 MCP 节点，DeepSeek Harness 智能体即可完成从数字信息处理到物理世界全域操纵的终极闭环。

## 系统集成蓝图与架构演进结论：构建全天候自演进个人智能体操作系统

综合上述对 13 项核心功能、13 篇 2026年9月至10月最新标杆学术论文以及 13 组高星 DeepSeek Harness 插件的深度剖析，可以清晰地观察到当代智能体工程的一条核心演进脉络：这 13 个功能模块绝非彼此孤立的特征堆砌，而是在 Cordis 时空可组合内核上相互赋能、互为因果的自演进有机体（Self-Evolving Organism）。
