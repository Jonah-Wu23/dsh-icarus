# M3.99：均衡联网搜索接入

日期：2026-10-16 · 状态：已实现，真实服务验收通过

实施依据：[PRD v1.3](PRD.md)、[M3 开发计划](M3_PLAN.md)、[M4 开发计划](M4_PLAN.md)与 [AGENTS.md](../AGENTS.md)。上游参考：[tianmingwan/dsh-balanced-search](https://github.com/tianmingwan/dsh-balanced-search)（MIT，`0.2.0`，main `6278313`，无 tag）。

## 1. 目标与关键假设

M3.99 让 Icarus 拥有一个可靠、免费额度清楚、失败如实可见的联网搜索能力。用户在 DSH 的插件设置页填入 Keenable、Exa、Tavily 中任意几家的 API key，按页面上的步骤教程完成申请，点一下就能看到连接测试结果和本月已用次数。委托执行、M4 的申请监测和关联调查都使用同一个搜索服务，每次调用的提供者、结果和用量进入证据与预算。

| 关键假设 | 撤掉后，结果是否成立 |
|---|---|
| 三家至少一家的免费额度可以注册并在国内网络环境调用 | 搜索能力不可用；原生来源与 Fetch、浏览器读取不受影响 |
| 桌面宿主 `0.2.0-rc.2` 的 `ctx.web` seam、`ctx.credentials`、`plugins.bundle.config` 槽位与私有 RPC 通道按已核查源码工作 | 已核查的接口签名失效，需要按新版本重新核查；第 3 节逐项登记了证据 |
| 用户愿意在本机 `~/.dsh/.credentials.yaml` 保存 key | 只能通过系统环境变量提供 key；设置页显示为只读来源 |
| 模型在调用搜索时不把个人资料原文写进查询 | 查询内容会发给第三方搜索服务；设置页如实说明数据去向，执行提示要求查询只写主题 |

执行决定：**按 MIT 许可把上游的三家客户端与轮换逻辑移植进 Icarus，作为 `dsh-icarus/search` 子入口实现，key 通过宿主凭据服务读取，设置页由 Icarus 自己的浏览器端模块提供；不安装上游插件。**

上游插件的签名与 `0.2.0-rc.2` 完全兼容，但直接安装有六个问题，每个都和 Icarus 的“暴露真实”与预算要求冲突：

| 上游行为 | 证据 | 对 Icarus 的影响 |
|---|---|---|
| 只从 `process.env` 读取 key，首次构建后缓存 `_balancer` | `index.js:293-307` | 无法在界面填写；换 key 必须重启 |
| 安装即接管内置 `web_search`，没有 key 时以 `WEB_PROVIDER_CONFIGURED_UNAVAILABLE` 失败且不回退 | `index.js:307,329`；`dsh-web/lib/index.js:124` | 装完未配 key，本机由 ds-bot `auto` 提供的现有搜索直接失效 |
| `balanced_search`/`balanced_fetch` 失败时返回 `isError: false` 的 `{error}` 字符串 | `index.js:462` 一带 | Icarus 的 ToolReading 把失败记成成功 |
| 401、429、额度耗尽走同一条错误路径，无退避；取消被报告为超时 | `index.js:63-70` | 无法区分认证失效与限流，故障单无法给出正确的修复入口 |
| 不读响应头与计费字段；Tavily 固定 `advanced`（每次 2 credits） | `requestJson` 实现 | 用量与费用不可追溯，免费额度消耗翻倍 |
| 抓取 `statusCode` 恒为 200；没有 `peerDependencies` | `index.js:355`；`dsh-app-boot/lib/index.js:286-292` | 原站 404 显示为成功；宿主兼容检查永远跳过该插件 |

修补上游需要重写读取 key、错误处理、用量记录三个核心部分，等同重写；移植后由 Icarus 统一维护，并在第三方说明中保留上游版权与许可。

## 3. 宿主兼容性

### 3.1 已核查的接口

核查对象：桌面 `E:/AI/dsh-harness` 与解包的 `.work/host-0.2.0-rc.2`，宿主包均为 `0.2.0-rc.2`，Cordis `4.0.4`。

| 能力 | 宿主事实 | M3.99 用法 |
|---|---|---|
| 搜索 seam | `ctx.web.registerSearchProvider/registerFetchProvider`；provider 契约为 `id`、同步 `available()`、`search(request, signal)`；请求只有 `query`、`maxResults`；结果 `{sources, truncated}`（`dsh-web/lib/index.js:67-140`） | 注册 provider `icarus-search`；`available()` 读取已配置状态，key 在每次请求时解析；接管默认关闭 |
| 注册生命周期 | provider 绑定调用方 fiber，插件卸载自动注销（Cordis traceable 代理，`cordis/lib/index.js:130`） | 重载不会出现 `WEB_DUPLICATE_PROVIDER` |
| 凭据 | `ctx.credentials.resolve/describe/set/unset`，每次操作重新读取；存储为 `~/.dsh/.credentials.yaml`；启动进程环境优先且只读 | key 引用名用 `KEENABLE_API_KEY`、`EXA_API_KEY`、`TAVILY_API_KEY`；换 key 下一次请求生效 |
| 浏览器端凭据 | 全局 `remote.credentials.describe/set/unset`，一次最多 64 个 ref，只返回 `{configured, source, writable}` | 设置页写 key、显示来源；页面永远拿不到 key 原值 |
| 设置页槽位 | `plugins.bundle.config`（key 为包名）显示在「插件 → 该插件详情」；`plugins.item` 属于官方插件分组 | 注册 `plugins.bundle.config`，key 为 `dsh-icarus` |
| 浏览器端模块 | `package.json` 的 `dsh.client = { platform: 'web', inject }` 与 `./client` 导出；产物以 `window.__ModuleLoader__.load` 包装；可直接 require react、`dsh-client-ui-slots`、`dsh-client-ui-primitives` 等基础模块 | 新增 `src/client/`，单独构建出 `lib/client.js` |
| 设置控件 | `SettingsSecretField`、`SettingsForm`、`SettingsFormModel`、`MarkdownText` 由 ui-primitives 导出 | 输入框与教程文字使用宿主控件，外观与官方设置一致 |
| 私有 RPC | 宿主端 `connection.rpc.handle('/icarus', handler)`，浏览器端 `connection.rpc.call('/icarus', method, args)`；传输层负责认证、来源校验与取消 | `0.2.0-rc.2` 的 getter 使用 connection 所属上下文，须经 `bindConnection` 绑定含 `webServer` 的插件上下文；连接测试与接管走认证通道 |
| 设置命名空间 | `configForms` 以 Loader 条目 id 寻址，只有 `.volatile()` 字段进入表单（`dsh-settings/lib/index.js:417-507`） | Icarus Config 的 `search` 子树标 `.volatile()`；`execution`、`demo` 保持组合期配置 |
| Config 导出 | 必须 `export default { name, inject, apply, Config }`（Loader 取 `exports.default`） | `src/index.ts` 按该形式补充 `Config` |
| 兼容检查 | 宿主只在 manifest 声明 `peerDependencies` 时检查版本（`dsh-app-boot/lib/index.js:286-292`） | 声明 `@deepseek-ai/dsh-web`、`dsh-credentials`、`dsh-client-ui-slots` 为 `>=0.2.0-rc.2 <0.2.1-0` |

### 3.2 已知限制与处理

| 限制 | 处理 |
|---|---|
| `.credentials.yaml` 为明文，Windows 上跳过权限检查 | 设置页写明保存位置与“本机明文保存，同一 Windows 账户的程序可读取”；建议每家使用 Icarus 专用 key，Tavily 设置月度上限 |
| 启动进程环境中已有同名变量时只读 | 设置页显示“来自系统环境变量，需在系统设置中修改”，输入框禁用 |
| 内置 `web_search` 不带时间范围，`web_fetch` 只有 url | Icarus 内部一律调用 `icarus_web_search`；接管只服务其他会话的普通搜索 |
| 全局 npm 中的 `@deepseek-ai/dsh` 是 `0.1.2-rc.1`，profile 目录裸 import 宿主包会解析到旧版 | 宿主端与浏览器端都不 import 宿主包，只经 `ctx` 注入使用；`@deepseek-ai/schemastery` 的解析结果在 M3.99.1 实测 |
| Cordis `4.0.4` 把声明的 `inject` 全部视为必需，`logger` 是上下文属性 | 搜索子入口仅声明 `credentials`；`icarus/tools` 与 `web/connection/webServer/configEditor` 分层动态注入，委托主链独立加载 |
| 非本机地址打开的 Web 页面不能写设置 | 设置页在该情况下显示只读状态与原因 |
| patch 中 `id` 或 `name` 不匹配时宿主只警告并跳过 | 接管开关写入用户 profile patch 的 `web` 行，整行重述 `searchProvider: icarus-search` 与 `fetchProvider: http`；启动时读取 `web` 行实际选中的 provider 回报设置页，写入未生效时显示“接管未生效”与实际 provider |
| `available()` 是同步方法，凭据读取是异步的 | 启动时与每次 key 变更后用 `credentials.describe` 刷新内存中的“已配置”状态，`available()` 读该状态；全部 key 移除时自动报告不可用，设置页同时提示关闭接管 |
| 接管后全部 key 失效，内置搜索不回退 | 开启接管必须至少一家连接测试通过；三家都进入认证失败状态时设置页与 Bot 故障单提示关闭接管，关闭即恢复 ds-bot 的 `auto` |

### 3.3 版本升级复核

宿主升级到 `0.2.0-rc.2` 之外的版本时，`peerDependencies` 使插件出现兼容警告。复核顺序：`ctx.web` 四个方法与请求结果结构、`credentials` 方法、`plugins.bundle.config` 槽位与页面属性、`connection.rpc` 通道规则、基础模块表。启动时 Icarus 分两层检查：设置面只依赖 `connection` 与 `webServer`，先注册 `/icarus` RPC；接管面再依赖 `web` 与 `configEditor`。缺少 `ctx.web.registerSearchProvider`、`ctx.configEditor.entries`、`ctx.credentials.resolve` 或 `connection.rpc.handle` 时，写入插件日志并在设置页列出具体缺失项，provider 不注册；缺少 `web` 或 `configEditor` 服务本身时，设置页同样列出服务名，搜索工具继续可用。复核结果写入本文件第 9 节并更新 `peerDependencies` 范围。

## 4. 搜索服务设计

### 4.1 三家客户端

| 提供者 | 搜索 | 抓取 | 计量 |
|---|---|---|---|
| Keenable | `POST https://api.keenable.ai/v1/search`，`mode: realtime`，`X-API-Key` | `GET /v1/fetch` | 每次 1 请求；免费每月 100,000，组织级 10 次/秒 |
| Exa | `POST https://api.exa.ai/search`，`x-api-key`，`numResults`，`startPublishedDate` | `POST /contents` | 记录响应中的 `costDollars`；每月 10 美元，另赠 10 美元注册奖励；本机按每月 10 美元控制 |
| Tavily | `POST https://api.tavily.com/search`，`Authorization: Bearer`，默认 `search_depth: basic` | `POST /extract`，`basic` | basic 每次 1 credit，advanced 每次 2 credits；每月 1 日重置 1,000 credits |

Tavily 默认使用 `basic`，`advanced` 只在调用方显式要求时使用，免费额度从约 500 次恢复到约 1,000 次。时间范围统一映射：Tavily 原生 `time_range`，Exa `startPublishedDate`，Keenable `published_after`。结果规范为 `{ title, url, content, publishedAt, score, provider }`，`publishedAt` 缺失时保持 `null`。

客户端只用 Node 内置 `fetch` 与 `AbortSignal`，JSON 用标准库解析。每次请求保存原始状态码、响应头中的限额字段（存在时）、响应体中的计费字段与请求耗时。

### 4.2 选择与故障切换

轮换不再是简单 round-robin。每家维护持久状态 `healthy / cooling / rate_limited / quota_exhausted / auth_failed / unconfigured`，选择时跳过非 `healthy` 的提供者，在健康提供者之间按剩余免费额度占比加权轮换，使三家额度同步消耗。

| 原始结果 | 分类 | 处理 |
|---|---|---|
| 400 key 格式错、401、403 | `auth_failed` | 停用该家，直到用户修改 key 或手动重新测试；生成按提供者去重的故障单 |
| 402（Keenable）、Tavily 额度耗尽 | `quota_exhausted` | 停用到已知重置时间（Tavily 次月 1 日，Keenable 次月），不知道时等用户重新测试 |
| 429 | `rate_limited` | 遵守 `Retry-After`，没有则冷却 60 秒；本次切换下一家 |
| 5xx、网络错误、超时 | `cooling` | 冷却 2 分钟，本次切换下一家 |
| 调用方取消 | `cancelled` | 立即停止，不再尝试其余提供者，不计为提供者故障 |

全部提供者失败时抛出 `SearchUnavailableError`，携带每家的分类、状态码与响应体前 500 字符。原生工具返回 `isError: true`，ToolReading 正确记录失败。

### 4.3 持久记录

追加迁移 `0009-web-search`：

| 记录 | 字段 |
|---|---|
| SearchProviderState | `provider`、`status`、`until`、`lastErrorRef`、`lastSucceededAt`、`updatedAt` |
| SearchCall | `id`、`provider`、`kind`（search / fetch / test）、`missionId`、`runId`、`sessionId`、`purpose`、`query`、`url`、`status`、`httpStatus`、`units`、`costDollars`、`resultCount`、`responseRef`、`startedAt`、`endedAt` |
| Mission | `bindings.searchBudget`：`{ perRun, perMonth, allowPaid? }`，属于 revision |

`SearchCall.units` 按提供者计量规则记录本次消耗，月度汇总按提供者的重置周期计算。查询原文进入 SearchCall，返回结果写入 Icarus 证据目录，`responseRef` 引用该文件；key 值不进入任何记录与日志，日志中的提供者错误不包含请求头。

### 4.4 预算

`SearchCall` 与 ModelCall 并列进入 Run 的使用统计。调用前检查 Mission 的 `searchBudget.perRun` 与 `perMonth`，超出时拒绝调用并抛出 `BudgetExhaustedError(reason=search)`，与模型预算采用同一处理路径。默认值：来源型委托每次执行 10 次，调查每次执行 20 次，每个 Mission 每月 600 次。Exa 返回 `costDollars` 时记录美元费用；免费额度内的调用记录为“免费额度内”，超出后的付费调用需要 Mission 授权，没有授权时该家标记为 `quota_exhausted`。

## 5. 设置页与操作教程

### 5.1 入口

用户打开 DSH 桌面「插件」页，点进 Icarus，详情页顶部即“联网搜索”卡片。Bot 在能力推荐或搜索故障单中给出同一入口的文字路径：“DSH 插件 → Icarus → 联网搜索”。首次加载 Icarus 且三家都未配置时，卡片顶部显示一行引导：“填一个 key 就能用，推荐先申请 Keenable，免费额度最多。”

### 5.2 卡片结构

卡片自上而下分为四块，全部使用宿主控件：

| 区块 | 内容 |
|---|---|
| 总状态 | 一句话结论，例如“2 家可用，本月已用 Keenable 132 次 / Tavily 41 credits”；内置搜索当前实际使用的 provider |
| 提供者三行 | 每家一行：名称与一句用途说明；`SettingsSecretField` 输入框（只显示“已保存”或“未填写”，从不回显）；来源标签（本机保存 / 系统环境变量）；状态徽标；“测试连接”按钮；“申请教程”展开链接；“移除”按钮 |
| 用量与额度 | 每家本月已用、免费额度、重置日期、最近一次失败的原始错误（展开查看）；数据来自 SearchCall，标明“按 Icarus 记录统计，厂商后台为准” |
| 高级 | “让 DSH 内置搜索也使用这些服务”开关；Tavily 搜索深度（基础 / 深入，附 credits 消耗说明）；数据去向说明 |

状态徽标与 4.2 节一致，用普通话表达：可用、未填写、key 无效、本月额度已用完（某日恢复）、请求太频繁（稍后自动恢复）、暂时连不上。每个异常状态旁给出下一步，例如 key 无效时显示“请到厂商后台确认 key 未被吊销，重新粘贴后点测试连接”。

保存后自动对该家执行一次连接测试：用固定查询 `DeepSeek Harness` 搜 1 条结果，计入 SearchCall（`kind=test`），显示命中条数、耗时与消耗。测试失败时显示分类后的原因与原始状态码，key 仍保留，方便用户先修正账户状态再重测。

### 5.3 申请教程

每家教程为三到四步，卡片内展开显示，文字同时写进 README 的“联网搜索”章节。链接与额度取自上游 [API_KEYS.md](https://github.com/tianmingwan/dsh-balanced-search/blob/main/API_KEYS.md)，实施时逐一打开官方页面核对后写入，并标注核对日期。

| 提供者 | 步骤 | 提示 |
|---|---|---|
| Keenable | 1. 打开 app.keenable.ai/login 注册登录；2. 进入 Console 创建 API key；3. 复制以 `keen_` 开头的 key 粘贴到上方输入框，点保存 | 每月 100,000 次免费请求，自动重置；不需要安装它的命令行工具 |
| Exa | 1. 打开 dashboard.exa.ai 用邮箱注册，免费档不需要绑卡；2. 打开 API Keys 页生成新 key，命名为 Icarus；3. 复制粘贴，点保存 | 每月 10 美元，另赠 10 美元注册奖励；擅长语义搜索与论文、技术文章 |
| Tavily | 1. 打开 app.tavily.com 注册，不需要信用卡；2. 在 API Keys 区域点 + 新建，Key Type 选 Development，Monthly Limit 填 1000；3. 复制以 `tvly-` 开头的 key 粘贴，点保存 | 每月 1 日重置 1,000 credits；基础搜索每次 1 credit |

教程末尾统一写三条：只填一家也能用，填多家会自动分摊额度；key 保存在本机 `~/.dsh/.credentials.yaml`，建议每家单独为 Icarus 新建 key；搜索词会发送给所选服务，Icarus 不把你的项目文件原文放进搜索词。

### 5.4 数据去向

高级区块显示：搜索查询与要抓取的 URL 发送给对应厂商；抓取由厂商服务器完成；返回结果保存在本机 Icarus 数据目录，作为成果证据；key 只在本机凭据文件中。该说明与 PRD 第 9.4 节的数据去向说明一致，M5 的委托卡沿用同一段文字。

## 6. 业务接入

### 6.1 原生工具

| 工具 | 参数 | 返回 |
|---|---|---|
| `icarus_web_search` | `query`、`maxResults`（1–20，默认 8）、`timeRange`（day / week / month / year）、`depth`（basic / advanced，仅 Tavily 生效） | `{ provider, results, callId, evidenceRef, units }`；失败 `isError: true` 与每家分类 |
| `icarus_web_fetch` | `url`、`maxChars`（默认 30,000，上限 50,000） | `{ provider, url, title, content, truncated, originStatus: null, extraction: 'vendor', evidenceRef }` |

`icarus_web_fetch` 的 `originStatus` 固定为 `null`，`extraction: 'vendor'` 表明正文由厂商服务器抽取、原站状态未知。证据核对把它的阅读范围记为 `vendor_extract`，与 Fetch MCP、浏览器的直接读取区分。正文读取的优先顺序写进执行提示：已绑定的 Fetch MCP 或浏览器优先，读取失败或被代理拦截时再使用 `icarus_web_fetch`。

两个工具在执行会话中调用时，结果自动经 `capabilities.capture` 进入 ToolReading，SearchCall 关联当前 Run 与 Mission；在普通 Bot 会话中调用时只关联 Session。

### 6.2 搜索来源

`icarus_sources` 新增 `adapter: 'search'`，`locator` 为查询式，`config` 保存 `timeRange`、`maxResults` 与可选的站点限定。每次轮询执行一次搜索，结果以规范化 URL 为原生 ID、以标题与正文摘要为内容指纹写入 Observation，沿用 M3 的去重、游标与健康状态。轮询默认每 6 小时，最短 1 小时，每次轮询计入该 Mission 的月度搜索次数。

搜索来源让申请案例、新开源项目这类没有固定 RSS 的主题能进入同一条评估与交付链；搜索结果只有摘要时，阅读范围记为 `snippet`，评估需要正文时由模型调用抓取工具补读。

### 6.3 能力目录与 Mission 绑定

`capabilities/catalog.ts` 增加 `web-search` 条目：提供者为 Icarus 内置，包名 `dsh-icarus`，用途“联网搜索与厂商服务端正文抽取”，认证方式“至少一家 API key”，免费条件列三家额度，连接入口为设置页路径。能力核查对该条目执行一次 `kind=test` 搜索：至少一家成功为 `available`，全部 `auth_failed` 为 `needs_auth`，全部未填写为 `missing`，其余为 `unavailable`。

需要搜索的委托在 `capabilityRequirements` 中声明 `tool: icarus_web_search`。必需能力缺失时沿用 M3 的阻止准备与故障通知，故障单附设置页入口；恢复后的重新核查与续接沿用 M3 机制。

### 6.4 可选接管内置搜索

开关默认关闭。打开时，宿主端注册 `icarus-search` provider，并在用户 profile patch 中写入 `web` 行 `{ searchProvider: icarus-search, fetchProvider: http }`；关闭时删除该行，恢复下层 bundle 的配置（本机为 ds-bot 的 `auto`）。改动 profile patch 需要重启宿主才生效，设置页在切换后明确提示重启，重启后回报实际生效的 provider。接管只替换搜索，`web_fetch` 保留宿主 `http` 的真实状态码与本地读取。接管产生的调用记为 `purpose=host-web-search`，进入 SearchCall 月度统计，不关联 Mission 预算。
