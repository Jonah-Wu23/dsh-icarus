# Icarus 开发计划

日期：2026-10-16 · 状态：M1、M2、M3 已完成；M3.99、M4–M6 待执行

实施依据：[PRD v1.3](PRD.md)、[M3_BEGIN 用户需求与扩展建议](M3_BEGIN.md)、[设计哲学](../PHILOSOPHY.md)、[AGENTS.md](../AGENTS.md)。Icarus 是 DeepSeek Harness 中专注科研与工程的个人 AI 搭档，从持续关注主题、发现重要变化并采取行动切入。首批用户聚焦热衷 Agent 与自动化的 AI 发烧友，尤其是其中的研究生与个人开发者。

当前插件工程、BotBridge 与 M2 委托执行链已建立，后续围绕来源采集与反馈推进。执行时结合项目背景与个人兴趣，解释发现的价值，在授权范围内交付研究材料和可运行代码。用户反馈影响下一轮选择与行动；桌面、QQ 与语音共享同一委托。

按需扩展进入同一业务链：用户按目标连接 MCP 或安装 DSH 插件，Icarus 核查当前工作区的真实能力，并将资料与工具绑定到 Mission。推荐优先采用免费软件与基础服务，明确托管额度和模型费用；接入状态按真实调用登记。

## 1. 关键假设与执行决定

| 关键假设 | 撤掉后，计划是否成立 |
|---|---|
| 首批用户有持续跟踪的主题，且有明确的研究或项目成果目标 | 执行机制仍可使用；当前场景选择与高频使用预期需要重新判断 |
| 桌面 DSH 与 DS Bot 能提供稳定身份、真实模型执行及审批接口 | 业务目标仍成立；当前插件接入方案失效，必须重新确定宿主接口 |
| 本机有可用模型配置，开发期间可访问实际公开来源 | 架构和代码开发可以推进；相关业务验收等待模型配置与来源恢复 |
| 常驻主机在约定时段在线 | 在线执行仍成立；持续监测与准点交付失效 |
| 专用 QQ 账号在 NapCat 中在线，本人好友私聊可用，成果页面可认证访问 | 桌面业务仍成立；QQ 验收等待账号上线、本人绑定与成果页可达 |
| 用户提供具体成果反馈 | 采集和交付仍成立；个性化改善及有用率评价缺少依据 |
| 选定扩展在桌面 `0.2.0-rc.2` 和任务工作区可用，所需账号已授权 | 原生来源可继续采集；依赖该能力的读取与行动暂停，完成连接后续接 |

执行决定：**先打通 BotBridge 与真实后台交付，再围绕同一条业务链建立任务、采集和反馈能力，最后完成跨端交互与持续运行验收。**

各阶段按工程依赖推进。首个发布版本完整覆盖 PRD 第 5 节，包含三个业务场景和有界调查，阶段完成以实际运行结果判定。

## 2. 工程结构与职责

采用 Node.js/TypeScript，SQLite 保存单主持久状态。插件使用宿主提供的模型与工具执行能力，前端接入宿主已有界面。

| 计划模块 | 职责与所有权 |
|---|---|
| `src/index.ts` | 插件注册、服务装配与生命周期清理 |
| `src/bridge/` | 版本化 BotBridge；解析 Bot 身份与当前 Session，连接已有长期记忆与任务上下文，交付后台成果 |
| `src/domain/` | Mission、Run 与成果契约；任务版本、预算和状态转换 |
| `src/storage/` | SQLite schema 与迁移；事务、租约、投递队列及个人数据导出删除 |
| `src/sources/` | RSS/Atom、arXiv、GitHub 和网页变化接入；游标、证据及来源健康状态 |
| `src/capabilities/` | 按目标推荐扩展，核查实时工具与认证状态，保存 Mission 绑定及 Run 能力快照；复用宿主安装与连接 |
| `src/context/` | 解析项目和个人资料引用，连接 Bot 已有记忆，保存本次实际读取的背景快照 |
| `src/execution/` | 调度、项目背景与偏好装载、宿主执行；关联发现与用户目标，核对成果要求并记录实际用量 |
| `src/feedback/` | 成果反馈与偏好版本；按 Mission 隔离，向执行服务提供当前版本 |
| `src/delivery/` | Bot 与 QQ 交付；OneBot 11 连接、本人绑定、消息回执与事件去重 |
| `src/client/` | 委托管理、成果详情和反馈；沿用现有文字与语音入口 |

这些目录在对应能力开始实现时建立。DS Bot 保持身份与聊天记忆的所有权；Icarus 保持任务和偏好的所有权。项目背景沿用 Bot 已有记忆及 Mission 中的目标与要求，任务偏好通过引用提供给 Bot。定时执行显式装载所需上下文，跨会话保持连续。接口名称在真实宿主接入时确定，计划中的模块名不作为上游现成 API。

## 3. 开发阶段

### M1：建立插件并打通 BotBridge（已完成）

依赖：当前 PRD 和已安装宿主。

实施内容：

- 核对桌面宿主 `0.2.0-rc.2` 与 `ds-bot@0.1.5` 的实际服务接口，确认插件加载、模型调用和审批入口。
- 建立插件 manifest 与 TypeScript 工程，按宿主要求固定依赖和构建方式，将真实构建命令写入 README。
- 实现 BotBridge 的身份解析、会话续接与成果交付，明确兼容版本和宿主认证方式。
- 现有接口缺失的操作通过维护在源码中的小范围扩展提供；把扩展纳入版本管理和安装流程。

交付：可被桌面宿主加载的插件；能够向绑定 Bot 交付一次真实来源的研究成果；可复现的本地构建与安装命令。

完成依据：主 Bot 在会话换代后仍能接收成果，并读取关联证据。后台调用拥有有效的宿主认证，错误保留原始状态。

### M2：建立持续委托与执行生命周期（已完成）

依赖：M1 的宿主接入契约。

实施内容：

- 实现 PRD 第 8.1 节的核心记录和数据库迁移，保存原始资料与成果引用。
- 支持创建、修改和暂停委托，完成取消与单次任务结束；每次修改产生新 revision。
- 建立 due time 调度、执行租约和代次检查；将重启恢复与旧版本成果提交统一纳入状态转换。
- 实现调用前预算预留和调用后结算，覆盖采集解释、反馈整理及重跑的全部模型调用。
- 将宿主审批绑定具体动作与 Mission revision，保留执行状态和原始错误引用。

交付：关闭窗口后仍保存的 Mission；可查看状态、用量和成果的单次 Run。

完成依据：重启后委托继续存在，成果提交遵循当前有效 revision；预算上限阻止新增调用；长期委托在一次交付后保持 active。

### M3：完成持续关注、按需扩展与交付

依赖：M2 的数据与执行服务；以 [M3 开发计划](M3_PLAN.md) 为详细实施依据。

实施内容：

- 接入实际 RSS/Atom、arXiv 和 GitHub 来源，连接公开网页变化来源；使用成熟解析库。
- 保存来源游标、发布时间与阅读范围，通过原生 ID 和内容指纹处理重复观测。
- 为 Mission 与 revision 保存个人资料引用、必需及可选能力、交付策略；核查当前工作区工具，以真实调用确认扩展可用于后台执行。
- 按完整目标推荐 MCP 或 DSH 插件，说明来源、准确包名与免费条件，复用宿主的安装和认证；用户选择的资料与工具绑定原委托。缺少工具或认证时显示配置入口，恢复后延续已保存进度。
- 执行时显式装载当前目标、相关项目背景与偏好版本，模型结合用户正在推进的研究或项目选择内容，解释发现与目标的关系；每批最多评估 20 条新增候选。
- 分开安排来源轮询、成果准备与到期投递；交付窗口和候选评估保存到数据库。日报按用户时区投递已准备成果，变化通知由模型判断是否值得报告；无合格内容和来源失败分别保存，空日报是否推送遵循用户设置。
- 用模型核对成果是否满足目标和阅读范围，程序校验结构与证据引用；持久化成果与 outbox，处理投递回执、发送结果未知和重启后的补交。

实施状态（2026-10-15）：第 5 节的迁移已应用到 schema v8。资料与能力绑定、四种原生来源、每批最多 20 条的候选评估、逐项要求核对、交付窗口及独立投递扫描均已实现；来源游标、原始证据与实际阅读范围持久保存，GitHub 请求额度跨进程共享。真实来源重复采集不增加观测，同一地址的内容变化产生新版本。桌面 `0.2.0-rc.2`、`ds-bot@0.1.6`、`dsh-mcp-manager@0.6.0`、`@anweat/dsh-browser@0.2.1` 与 Fetch `2026.10.10` 已在所选后台工作区真实调用。准点交付、修改已准备任务、宿主重启续接及连接撤销恢复的实际结果见 [M3 开发计划](M3_PLAN.md) 第 9 节。

交付：可结合个人背景持续跟踪论文和开源项目；按需求推荐并连接扩展，来源证据与投递状态可查询；有价值的发现可供 M4 关联调查使用。M3 通过服务和已有 Bot 交互完成，完整管理界面在 M5 交付。

完成依据：真实论文成果按时进入绑定 Bot，开源项目变化说明对当前项目的具体价值；选定个人资料和扩展能在后台执行会话使用，记录阅读范围。至少一项 MCP 与一项 DSH 工具完成本机实际调用，缺少能力和认证时状态可见；会话换代和重启后绑定与进度继续存在。已提交成果不重复生成，发送结果未知时进入 `delivery_unknown`。候选目录中其他扩展按其各自验证状态展示。

### M3.99：接入均衡联网搜索

依赖：M3 的能力绑定、证据与预算服务；以 [M3.99 开发计划](M3.99_PLAN.md) 为详细实施依据。

实施内容：按 MIT 许可移植 Keenable、Exa、Tavily 三家搜索客户端，key 经宿主凭据服务读取；在「插件 → Icarus」详情页提供 key 填写、连接测试、用量与申请教程；提供 `icarus_web_search`、`icarus_web_fetch` 与 `search` 来源，调用进入证据与预算；声明桌面 `0.2.0-rc.2` 兼容范围并在启动时核查宿主接口；可选接管内置 `web_search`。

完成依据：设置页填入的 key 无需重启即生效，三家真实调用与故障分类正确，搜索调用进入 Run 证据与预算，页面与日志不出现 key 原值。

### M4：完成三个场景、反馈与进一步调查

依赖：M3 的完整成果链与 M3.99 的联网搜索；以 [M4 开发计划](M4_PLAN.md) 为详细实施依据。

实施内容：

- 完成论文、申请动态和兴趣作品三个模板，共用 Mission 服务，分别定义成果要求与偏好。
- 申请案例保留项目全名与申请轮次，关联原始出处；模型提出转载合并，保留各来源证据。
- 兴趣策展读取真实图像内容，保存作者与原站链接，按来源权限展示预览。
- 实现卡片反馈与自然语言纠正，关联具体成果，保存明确要求和可撤销的偏好推断；下一次执行装载新版本，解释选择如何变化。偏好按 Mission 隔离，打开链接仅记录阅读行为。
- 将成果转成关联 `investigate` 委托，支持全文精读、方法比较和本地文档交付；新开源项目可形成面向当前项目的集成判断，工程调查按用户规格生成代码，使用项目标准命令实际运行并记录产物与结果。
- 关联调查继承原发现的背景与能力引用，在已有授权下使用代码、浏览器或个人资料工具；日历、邮件和内容平台按具体需求选装，外部动作绑定具体授权。MCP 或插件内部调用的费用纳入成果成本，未知用量如实保存。
- 成果表达明确判断、关键假设与行动建议；说明撤掉关键假设后的结论变化，缺少证据时明确下一项调查。
- 实现已授权范围内的主动调查，每个委托最多同时运行一次，每次最多 10 分钟、8 次模型请求，并遵守配置的 token 上限；主 Bot 直接读取成果并解释自己的判断。扩大范围前提交具体动作，转为另一项长期委托由用户决定。

交付：三类委托完整可用；用户反馈影响后续选择与行动，减少重复信息与操作；从发现继续调查得到研究材料或可运行代码。

完成依据：兴趣反馈只进入对应 Mission，并能在后续成果中观察到采用；论文与 GNOSIS 的比较文档引用真实资料，工程调查形成有来源依据的集成判断与实际运行结果。调查成果明确说明如何推进原有目标；达到预算时保存实际进展，原有监测继续存在。

### M5：完成桌面、QQ 与语音交互

依赖：M4 的任务、成果和反馈契约；专用 QQ 账号、本人好友私聊与可用语音服务。QQ 通信契约以 PRD 第 9 节为准。

实施内容：

- 实现首页、可编辑委托卡和成果详情，围绕“今天值得看什么”和“你交代的事情进展如何”展示发现与进展，提供来源及下一次交付时间；提供个人数据导出与删除。
- 在委托卡显示所需能力、连接状态和资料范围，连接宿主插件市场与 MCP 设置入口；反馈按钮携带成果身份，GenUI 等呈现插件通过 Icarus 服务保存反馈。扩展卸载或认证失效时显示对具体委托的影响。
- 接入 NapCatQQ 的 OneBot 11 正向 WebSocket，按下表完成本人绑定、准点发送与反馈回传。
- 为手机访问提供经过认证的成果页面，验证实际远程可达性；审批答复关联宿主当前有效 request ID。
- 接入现有语音，确认识别模型就绪；语音创建委托和追问成果携带对应成果 ID。
- 通过界面明确区分停止朗读、结束语音和取消委托，显示模型与通知渠道的数据去向。

交付：同一委托可在桌面管理、手机反馈，并通过语音追问成果。

QQ 按以下依赖顺序实施，全部通过后完成 M5：

| 步骤 | 实施内容 | 真实完成依据 |
|---|---|---|
| M5.1 协议服务 | 独立部署 NapCat，登录专用 QQ，登记安装版本与许可；OneBot 服务仅监听本机，启用 token 与数组消息格式 | `get_login_info` 对应所选账号，`get_status` 在线；连接断开在桌面显示具体状态 |
| M5.2 本人绑定 | 桌面生成一次性绑定码，本人好友私聊提交后保存 Bot、发送账号与本人接收身份关系；提供解除绑定 | 本人手机绑定成功；任务读取与操作严格校验绑定身份；解除绑定停止后续 QQ 发送 |
| M5.3 成果投递 | 为既有 outbox 增加 QQ 适配器；调用 `send_private_msg`，以 `echo` 关联响应，保存 `message_id` 与成果关系 | 无需用户事先发消息，在约定时间收到真实简报；明确失败与 `delivery_unknown` 可查看，重启不重发已确认投递 |
| M5.4 反馈与调查 | 引用消息定位成果；模型解释自然语言反馈与追问，经既有服务保存偏好或创建有界调查；持久保存入站事件身份 | 同一条重复事件只产生一次业务操作；反馈进入下一次执行，调查使用原成果证据 |
| M5.5 审批与恢复 | 审批绑定本人、当前宿主请求及 Mission revision；重连后重新核查在线身份，保留发送结果未知的状态 | 本人批准当前请求后动作才执行；过期请求拒绝；实际断线、NapCat 重启与 DSH 重启后任务和回执仍可核查 |

完成依据：本人 QQ 在约定时间实际收到简报并回传反馈；语音关闭后委托继续存在；过期审批不执行动作；导出和删除覆盖关联数据。OneBot 成功响应记录为渠道接受，手机实际收到单独作为端到端验收结果。

### M6：完成持续运行验收与发布准备

依赖：M1–M5 全部完成。

实施内容：

- 在真实桌面宿主、实际来源及本人账号上运行 PRD 第 11 节的完整场景。
- 使用真实委托验证宿主重启与会话换代，检查任务连续性、版本隔离和投递恢复。
- 在实际运行中核对预算统计、失败记录及反馈采用，确认相关背景跨会话连续、反馈实际改变后续结果，关联调查推进原有目标；保留验收所需证据，敏感值不进入日志或仓库。
- 核查所选扩展在实际桌面版本和工作区的调用、认证恢复与费用条件；扩展失效后任务保留进度，重新连接可继续，资料导出删除覆盖新增快照与评估记录。
- 完成标准构建与可安装产物验证，更新 README 中的安装、启用及运行命令；登记实际引入的第三方依赖和许可证。

交付：满足完整发布范围的安装产物；可复现的使用方式；真实业务验收结果。

完成依据：PRD 第 11 节全部场景通过，应用构建通过。未完成的验收明确保持待完成状态。发布操作在产物与验收结果可审阅后请求批准。

```mermaid
    M6 --> V[14 天真实使用评价]
```

每个阶段完成后连续推进下一项依赖已满足的任务。外部条件阻塞时，保留具体失败与缺少的条件，继续完成不依赖它的工作。例如，QQ 登录或绑定缺失时仍可推进桌面成果页和语音接入，QQ 验收保持未完成。

各阶段记录实际开始与完成日期，按完成依据推进。后续日历安排依据已经验证的宿主接口与实际开发进度确定。

每项改动运行与其范围匹配的标准构建或真实联调。验证通过且没有新疑点时进入下一项任务。验收采用 PRD 已定义的业务场景，执行记录中的成功必须对应实际产物。

## 5. 真实使用与商业托管

完整功能通过验收后，开展连续 14 天的真实使用评价。先由本人持续使用三个场景，再招募 PRD 定义的 20–30 位目标用户，聚焦已有 DSH 使用习惯、热衷 Agent 与自动化的研究生和个人开发者；对外邀请在内容与体验入口准备完成后请求批准。

记录每位活跃用户每周明确认可或实际采用的成果数，核对准点交付率与完整使用成本。目标采用 PRD 第 10 节：准点交付率 ≥95%，有明确评价成果的有用率 ≥60%，每名持续使用者每周至少 3 次有价值成果，来源及纠正可追溯率为 100%。

结合具体成果观察发现如何推进研究或项目，以及反馈是否减少重复信息与操作；同一成果跨渠道交付只计一次。稳定人格与兴趣策展服务长期互动，角色互动和 AIGC 创作作为后续扩展方向。

同时记录从表达需求到扩展真实可用的结果，观察连接后的工具是否产生被用户采用的成果。免费软件、平台免费额度与付费模型消耗分别展示，计入持续使用成本；推荐或安装次数只用于观察配置过程。

托管报价实验采用 39 元/月、BYOK、5 个活跃委托。至少 20 名完成体验的用户中有 3 名实际支付，且逐用户成本计算为正贡献后，推进商业托管。支付条件成立前，工程重心放在持续交付质量和可维护的自托管安装；商业部署与收费动作准备好具体方案后请求批准。
